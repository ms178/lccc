Broaden FP Vectorization Beyond the Reduction Idiom
====================================================
Priority: HIGH

Problem
-------
The reduction vectorizer (sum/dot, AVX2/SSE2) is in place and beats GCC on the
simple reduction kernel, but three FP-heavy benchmarks still lag badly:
spectral_norm 9.3×, nbody 3.9×, mandelbrot 3.2×. GCC vectorizes these general
FP inner loops (and fuses FMA); LCCC emits scalar `mulsd`/`addsd`.

What GCC does that LCCC doesn't
-------------------------------
1. **Loop vectorization of non-reduction loops** — elementwise `a[i] op b[i]`
   bodies with independent outputs (not just reductions), using packed ops and
   a remainder loop.
2. **FMA fusion** — `a*b+c` chains fused to `vfmadd`, halving the FP-op count.
3. **SLP vectorization** — packing the independent scalar ops inside one basic
   block (e.g. the two or four `x`,`y`,`z` component computations in nbody).

Plan
----
1. **Extend the loop vectorizer** from reductions to elementwise/independent
   loops (detect no loop-carried dependency on the output, rewrite body to
   packed intrinsics, add remainder).
2. **Add FMA fusion** to the FP peephole / instruction selection: recognize
   `mul` feeding an `add` and emit `vfmadd231pd`.
3. **SLP-lite**: pack 2–4 independent scalar FP ops in one block into one SIMD
   op when their addresses/offsets are affine and contiguous (targets nbody).

Risks
-----
- Correctness: alignment, aliasing of the arrays, and exact FP semantics. Start
  with the same conservative no-aliasing/alignment checks the reduction
  vectorizer already uses; never reassociate FP without an explicit fast-math
  flag.

Measurable success
------------------
- spectral_norm / nbody / mandelbrot ratios drop toward ~1.5× or better.
- No correctness or suite regression; bounded code growth.

Key files
- src/passes/vectorize.rs, src/backend/x86/codegen/intrinsics.rs
- reference: LLVM LoopVectorizer + SLP, GCC tree-vectorize, Intel FMA guidance.

# 2026-08-18 — live four-oracle SIMD/FP corpus and guarded FMA coalescing

## Accomplished

- Added a standalone 50-function strict/fast SIMD/FP corpus and live CE
  scoreboard for GCC 16.2, Clang 22.1.0, ICC 2021.10, and latest ICX.  See
  `docs/simd-fp-oracle.md` for reproducible commands, parser limitations, and
  the full baseline summary.
- Closed three correctness hazards before optimizing: strict reductions retain
  source order; umbrella `-ffast-math` defines `__FAST_MATH__`; unrestricted
  pointer roots no longer receive an implicit noalias assumption, while C
  `restrict` propagates to IR `noalias`.
- Implemented alias-guarded scalar destructive-FMA destination coalescing.
  `p50_distance3_f64` is 28 -> 22 instructions (best oracle 9).  Runtime and
  assembly regressions cover direct, alias-fallback, and stack-argument shapes.
- Added ordered caller-saved/ABI parameter homes for one-block leaves.  p50 is
  now 14 instructions; a 50-pattern A/B changed only p50 (-8), with no static
  regressions. VM paired timing was suggestive but inconclusive.
- Folded proven single-use scalar FP loads into adjacent VEX arithmetic: 12/50
  patterns improve, none regress, and p50 reaches 11 instructions. A randomized
  paired stencil5 VM screen improved 13.1% (ratio 0.8694, CI 0.8474..0.8930).
- Added exact-class, width-aware XMM/YMM homes for loop-carried F32/F64
  reductions. Five patterns improve with no regression; sum+dot paired VM
  screening measured ratio 0.5021 (CI 0.4589..0.5908), 23/24 wins.
