Use-Def Chains: the Shared Optimizer Context (UPDATE)
=======================================================
Priority: HIGH (still the single highest-leverage optimizer change)

Status: still OPEN. `ideas/high_use_def_chains.txt` (2026-01-29) remains the
canonical design. This is an update tying it to the current pipeline and to the
PGO work that landed since.

Why it matters more now
-----------------------
The pass pipeline has grown (14+ passes, post-structural inlining, PGO). Every
pass still re-scans all instructions. With PGO in the picture, the absence of a
use-def context also blocks two PGO-specific wins:

1. **Forward constant/copy propagation after inlining.** PGO force-inlines hot
   call sites; the freshly-inlined body then has many `Copy`/constant operands
   that only a use-def-aware constant propagator can fold into the caller.
   Without it, force-inline gains are partially lost downstream.

2. **Profile-guided value specialization.** Once constant propagation can reach
   users, a hot call site whose argument is *often* a constant (recorded by the
   PGO value profiler for indirect calls today, extendable to direct calls) can
   be specialized — clone the loop body for the hot constant value. This is
   classic LLVM `-pgo-icall-promotion`-plus-constant-specialization.

What changed since the original note
------------------------------------
- `dce.rs` still builds `collect_used_values` by walking everything.
- `constant_fold.rs` still cannot propagate a folded value to users.
- `gvn.rs` still replaces a redundant instruction with a `Copy` but does not
  rewrite users.

Concrete next step
------------------
1. Add `UseDefInfo { defs: HashMap<Value, InstRef>, uses: HashMap<Value, Vec<InstRef>> }`.
2. Build it once before `run_passes`; update incrementally in the hot mutators
   (instruction replace/delete/operand rewrite).
3. Route DCE's liveness check through `use_count == 0`.
4. Teach `constant_fold`/`copy_prop`/`simplify` to rewrite downstream users.
5. Add a unit test proving a PGO force-inlined body is constant-folded after
   propagation (tie to `inline_pgo`).

Measurable success
------------------
- Compile time: fewer full IR scans per function (O(passes·insts)→O(1) per value).
- Code quality: forward const/copy propagation turns more PGO force-inlines into
  net wins; a reduction in post-inline `mov`/`movl` copies.
