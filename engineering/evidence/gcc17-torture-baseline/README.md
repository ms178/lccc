# GCC 17 native differential baseline

Four inventories were captured from [run 42817930714](https://github.com/ms178/lccc/actions/runs/42817930714), head `470a775acdda2cb622ebe1873e2706b52dee2cb3`, the merge of #1171 (`-fpack-struct[=<n>]`, x86 `-mcpu=`, sema scaling). The run's ratchet step failed for exactly one reviewed reason per target -- `["pr67106.c", "-O2"]: compile-fail -> pass` -- because #1171 implemented `-fpack-struct`; see `REBASELINE-2026-11-10-dwarf-pack.md` for the full review, the independent GCC/Clang layout proof, and the explicit statements of what is *not* fixed. All case counts, statuses, phases, return codes and bounded diagnostic digests other than that one row matched the previous successful baseline from [42533647855](https://github.com/ms178/lccc/actions/runs/42533647855), and matched the immediately preceding [42535980102](https://github.com/ms178/lccc/actions/runs/42535980102) whose overall failure was the intentional `runner_sha256` identity change. Each matching `GCC torture inventory` annotation had zero omitted rows. Its `GCC torture provenance` identity and all numbered `GCC torture outcome evidence` chunks were joined by architecture/mode; chunk numbering, case triples, counts, unique keys and absence of reference failures were checked before writing these files, by `scripts/torture_ci_capture.py --allow-ratchet-failure`. Outcome rows record test, flags, status, phase, return code and SHA-256 of the runner's bounded detail. They are not full diagnostic logs.

The scheduled/main/whole-corpus dispatched job compares validated complete reports with these four reviewed inventories. Any changed non-pass outcome, including a fix or changed diagnostic, fails for explicit review; reference failures are never accepted. Filtered dispatches do not use the ratchet and are marked advisory. The workflow is not currently a pull-request-required check. A changed corpus, selected sources, local dependency fingerprint, runner/support modules, target, configuration, oracle driver, image/version or search-environment fingerprint refuses comparison. An image update may therefore require re-establishing the baseline even if compiler results did not change.

For a rebaseline, first run the whole pinned corpus on both targets, then save the GitHub API run and job metadata (`gh api repos/ms178/lccc/actions/runs/RUN` and `.../runs/RUN/jobs`) and each target job's annotations (`gh api repos/ms178/lccc/check-runs/JOB/annotations --paginate`) as `JOB.json`. Pass these to `scripts/torture_ci_capture.py --run RUN.json --jobs JOBS.json --annotations-dir ANNOTATIONS --out-dir EMPTY_DIRECTORY`. It requires both complete campaign/publication steps, all outcome chunks, no omitted cases, matching identities/counts and no reference failures. A ratchet failure requires explicit `--allow-ratchet-failure`, complete error annotations and separate human review. API JSON files are not independently authenticated by the script: retrieve them directly with `gh` and verify the run/head. Inspect report artifacts when available and review every changed case and diagnostic; never replace a known failure with a skip merely to obtain green. Compare proposed baseline changes in code review, then run the ratchet again.

This is not a hermetic oracle: host system headers, CRT, assembler/linker, external libraries and kernel are not fully content-pinned; the local include walker is bounded and handles quoted local includes, not all preprocessor dependency forms. GCC prefix files are checked against the trusted extracted-tree digest separately. Hashes and image version improve comparability but do not establish complete reproducibility or general compiler correctness. The native subset is not full DejaGnu, nor a measurement of generated-code performance.
