# GCC 17 native differential baseline

Four inventories were captured from successful whole-corpus [run 42533647855](https://github.com/ms178/lccc/actions/runs/42533647855), head `3d168f0fe76561b7bb96d23214814c3e1b1d8d3e`. Each matching `GCC torture inventory` annotation had zero omitted rows. Its `GCC torture provenance` identity and all numbered `GCC torture outcome evidence` chunks were joined by architecture/mode; chunk numbering, case triples, counts, unique keys and absence of reference failures were checked before writing these files. Outcome rows record test, flags, status, phase, return code and SHA-256 of the runner's bounded detail. They are not full diagnostic logs.

The scheduled/main/whole-corpus dispatched job compares validated complete reports with these four reviewed inventories. Any changed non-pass outcome, including a fix or changed diagnostic, fails for explicit review; reference failures are never accepted. Filtered dispatches do not use the ratchet and are marked advisory. The workflow is not currently a pull-request-required check. A changed corpus, selected sources, local dependency fingerprint, runner/support modules, target, configuration, oracle driver, image/version or search-environment fingerprint refuses comparison. An image update may therefore require re-establishing the baseline even if compiler results did not change.

For a rebaseline, first run the whole pinned corpus on both targets, check the run/head and job conclusions, then retrieve all check annotations from the relevant run's two job IDs, e.g. `gh api repos/ms178/lccc/actions/runs/RUN/jobs` followed by `gh api repos/ms178/lccc/check-runs/JOB/annotations --paginate`. Inspect the report artifacts when available and review every changed case and diagnostic. Require complete inventory annotations with `nonpass_omitted: 0`, all ordered outcome chunks, matching case identities/statuses and counts, no reference failures, matching provenance, and a verified current report. Never replace a known failure with a skip merely to obtain green. Compare the proposed baseline change in code review.

This is not a hermetic oracle: host system headers, CRT, assembler/linker, external libraries and kernel are not fully content-pinned; the local include walker is bounded and handles quoted local includes, not all preprocessor dependency forms. GCC prefix files are checked against the trusted extracted-tree digest separately. Hashes and image version improve comparability but do not establish complete reproducibility or general compiler correctness. The native subset is not full DejaGnu, nor a measurement of generated-code performance.
