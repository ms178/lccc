# MS-03 / MS-10 — regression and SSA-validation CI enablement

**Date:** 2026-09-06

**Base:** `aae69e2b` (upstream `main`, after PR #422)

**Scope:** make the existing full regression corpus a practical CI gate with
`CCC_VALIDATE_SSA=1`, and add a deterministic linker-fuzz smoke beyond library
unit tests.

## Why the CI step was not added blindly

The first full local validator run exposed **20** failures in 677 corpus cases
(644 pass, 20 fail, 13 GCC-reference skips).  Adding the workflow step at that
point would merely have made every PR red.  The failures separated into
validator false positives / crash paths and genuinely non-canonical IR emitted
by the PGO runtime builders:

| Finding | Resolution |
|---|---|
| `next_value_id == 0` means “unknown; scan when needed”, but the validator treated it as an upper bound of zero | Preserve the documented sentinel semantics; a nonzero cache remains a strict upper bound. |
| A CFG-dead phi predecessor is represented by `usize::MAX` in `idom`; validator indexing panicked | Skip only the non-executable incoming edge and retain failure behavior for reachable predecessors. |
| Fixed `Alloca` is a function-frame declaration, yet inlined vector IR can retain it after an address user | Exempt only fixed `Alloca` from straight-line order checking; `DynAlloca` remains an ordered definition. |
| PGO helpers duplicated raw `ParamRef` instructions, published a pre-plumbing watermark, and mixed non-Copy definitions into post-phi joins | Make `push_helper_fn` the sole parameter-setup owner, publish its final cursor, and use copy-only conventional-SSA joins with separate address/load IDs. |
| The i686 over-aligned-argument test wrote an `unsigned` lvalue into a character member, then read it as characters | Replace the undefined-aliasing probe with explicit little-endian byte helpers.  This preserves the ABI assertion and passes GCC 14.2 at `-O0`, `-O1`, `-O2`, and `-Os`. |

The validator now rejects stale nonzero watermarks and ordered dynamic-stack
uses exactly as before.  Its new focused unit coverage includes the zero
sentinel, stale nonzero cache, unreachable predecessor, fixed alloca, dynamic
alloca, PGO helper parameter ownership/watermarks, and dump-helper joins.

## CI contract

`.github/workflows/ci.yml` now runs, after the existing release build and unit
tests:

```sh
CCC_VALIDATE_SSA=1 python3 tests/regression/run_regression.py \
  --lccc target/release/lccc -j 2 --json regression-results.json
```

The JSON result is uploaded even on failure.  Two workers are intentional:
they exercise independent compiler/linker processes without oversubscribing a
standard GitHub-hosted runner while preserving the corpus runner's per-test
90-second timeout.

The same job also runs bounded, seeded linker fuzzing:

```sh
FUZZ_N=128 FUZZ_SEED=20260906 LCCC_LD="$GITHUB_WORKSPACE/target/release/lccc-ld" \
  python3 tests/linker/fuzz_ld.py
python3 tests/linker/fuzz_elf_grammar.py \
  --lccc "$LCCC_LD" --iters 64 --seed "$FUZZ_SEED"
```

This supplies a reproducible MS-03 fuzz smoke rather than an unbounded,
non-reproducible CI cost.  It covers malformed-byte handling plus grammar-built
ELF inputs across executable, shared, relocatable, script, GC/ICF, and
`--emit-relocs` routes.

## Deliberate limits

This change does not enable a networked Compiler Explorer gate (MS-01): that
remains a separate reproducibility/security decision.  It also does not claim
that a CI VM yields meaningful runtime speed measurements.  The assembly A/B
is recorded only to prove this hygiene fix did not perturb generated
instructions; runtime/codegen optimization work follows under its own
checksum-verified benchmark gates.
