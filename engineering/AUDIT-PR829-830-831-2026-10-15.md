### RISC-V review decision for #829

The correction to the shared GOT relocation number is directionally important: the PR notes that the current `R_RISCV_GLOB_DAT = 6` value aliases `R_RISCV_TLS_DTPMOD32` in the RISC-V psABI, and uses symbol-based `R_RISCV_64` relocations for covered preemptible GOT/data-pointer cases. But the 216-case matrix does not cover `R_RISCV_32`. The current `R_RISCV_32` path computes and writes `S + A` directly, so a shared-object/preemption claim needs a case that distinguishes a link-time absolute value from a loader-resolved symbol value. Add that case across local, default-visible/preemptible, hidden/protected, undefined, and absolute-symbol combinations, then run the 13 loader/interposition cases under the target loader. Also review unresolved strong `STV_PROTECTED` handling. Without those proofs and a clean rebase, carrying the entire 436-file PR into #831 would multiply risk rather than improve this patch.

## High-confidence changes made in this working tree

### FXRSTOR liveness

`FpLiveness` previously modeled state-save reads but did not model definite state-image restore writes. Consequently, a legacy `movaps %xmm6, %xmm7` could appear live across `fxrstor` when the restored XMM7 value was read later, preventing a safe dead-move elimination. The new effect transfer treats `fxrstor`, `fxrstor64`, and `fxrstorq` as writes to low XMM0–15 only. It leaves YMM/ZMM upper regions live and deliberately does not kill anything for XRSTOR/XRSTORS, whose actual component writes depend on runtime masks and state-bitmap conditions.

Added tests exercise all three FXSAVE-format spellings, verify low-XMM kills at XMM0, XMM7, and XMM15, assert the legacy move is removed by `eliminate_dead_fp_moves`, and check both YMM-high and ZMM-high preservation. A red-team pass caught a weakness in the first production-pass regression: `parse_fp_reg_move` accepts XMM operands only, so a YMM-to-YMM candidate would never enter that pass. The test now uses an XMM-width VEX producer (the actual pass input) followed by a YMM or ZMM read, which makes its upper-zeroing write observable; XRSTOR-family checks cover XMM7 and XMM15. These expanded Rust tests are not locally compiled and are pending the updated hosted CI run.

### Failure diagnostics

The frontend GCC16/i686 provisioning step captures and prints its install log and emits an Actions error annotation with the last useful lines on failure. The strict linker runner emits an Actions annotation for each failure (and strict warning/skip), including the case name and detail. Run `38714867593` exercised the linker annotation and exposed a strict skip: `plain_gotpcrel_relaxation` was assembled by GCC's configured distro GAS, which did not understand MOVRS, instead of the pinned GNU as 2.47 already on `PATH`. The strict skip policy was correct; I changed that fixture to invoke an explicit `LCCC_TEST_ASSEMBLER` and wired the pinned tool path through both hosted and local CI. Local GAS 2.40 reproduces the expected skip; only the next hosted run can verify the fix with the pinned 2.47 binary. The provisioning-success path does not exercise its failure annotation. Three offline tests mock both provisioning success and failure, verify `%`/newline escaping, ensure QEMU setup is skipped on GCC failure, and check preservation of exit status 23. These changes improve diagnosability; they do not claim to fix any underlying linker defect.
