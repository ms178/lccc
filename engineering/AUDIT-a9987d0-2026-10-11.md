## Confirmed current-fork defect: intermediate SWAR casts disappear

Incoming `src/passes/bit_idioms.rs:21–60` peels **all** integer casts to find
arithmetic nodes. The local fork had improved several value identity checks,
but structural `binop()` traversal and two shared-value checks in popcount
still retained the unsound assumption that final masks make casts irrelevant.

Reduced, defined-behavior reproducer:

```c
unsigned low16(unsigned x) {
    x -= (x >> 1) & 0x55555555u;
    x = (x & 0x33333333u) + ((x >> 2) & 0x33333333u);
    x = (unsigned short)(x + (x >> 4)) & 0x0f0f0f0fu;
    return (x * 0x01010101u) >> 24;
}
```

On this x86-64 target `low16(~0u)` must return **16**, not **32**. Before the
fix, the v3 assembly was a full-width `popcntl` followed by a return-register
move and `ret`. The generic target also miscompiled; this is not an ISA issue.
The committed regression reports on baseline:

```text
FAIL ffffffff: 32 32 32 32 32 (expected 32 16 8)
```

The five actual expected results are `32 16 8 16 16`. With the fix the complete
4,096-input test passes, including zero, all-one, every single-bit input and
seeded unsigned LCG inputs. No implementation-defined signed overflow or
out-of-range shifts are used.

### Repair and proof obligations

1. Structural BinOp matching traverses **Copy only**, not integer casts.
   This also closes that structural hole for other users of the shared helper.
2. Every SWAR arithmetic node must be I32/U32, not just the first subtraction.
3. The two shared partial-count operands must be identical values modulo
   copies, not merely descend from the same pre-cast root.
4. The terminal intrinsic retains the original input value; no codegen or
   target ISA policy is changed.

The rewrite remains local, deterministic and bounded. No new analysis, IR
allocation, superoptimizer, source-specific special case or global pass
shutdown is introduced. Width-changing variants fall back to their existing
scalar lowering. This is deliberately conservative: proving an additional
cast transparent requires a separate range/bit proof, not a blanket exception.

Two SWAR Rust tests add 44 internal-edge Copy/cast cases and 48 per-node width
rejections. The C gate checks five source shapes, all four optimization levels,
reference stdout and nonzero exits, plus positive/negative POPCNT assembly
contracts. The prior `bit_idiom_soundness.c` also passes with SSA validation.
The compile-only v3 contract does not require POPCNT support on the test host.

## Second confirmed defect: casts between CLZ select stages

After the first repair, an adjacent structural matcher still used the same
unsound cast peeling for `Select`. A 32-bit binary-search CLZ network with
`x = (unsigned short)x` immediately after the 16-bit stage returns **31** for
input 2. The S02 compiler (BinOp repair only) returned **30**, having recognized
a CLZ of the untruncated input. This is independently executable, not merely a
possible problem inferred from the source.

`select()` now traverses Copy only as well. The shared helper serves both
CLZ and CTZ networks. The separate CTZ probe returned the correct 31 before
the second repair; no CTZ miscompile is claimed. A third Rust test checks direct/copy acceptance and
truncation/extension rejection at U32 and U64 (eight assertions). The new
`count_zero_intermediate_casts.c` tests 4,096 inputs for four shapes: canonical
and truncated CLZ32 and CTZ64. Expectations use separate bit-at-a-time loops,
with explicit handling of the portable networks' zero results (31 and 63,
not the intrinsic widths). GCC ASan+UBSan also passes.

The new fast gate therefore covers **four C programs × four optimization
levels**, not just the first SWAR reproducer. The canonical controls remain
mandatory; refusing an unsafe pattern must not disable correct recognition.

## Third confirmed defect: defined CLZ zero case changes value

The positive canonical control exposed another inherited defect:
`clz_full(0)` returns **31** in the portable five-stage network, but both the
baseline and the select-only repair returned **32**. GCC returned 31. Merely
checking the cast attack would have missed this independent boundary bug.

The lowering is now `Clz(x | 1)`. Proof: for nonzero x, setting bit zero cannot
change its highest set bit; for zero, the operand becomes 1 and CLZ32 returns
31. This also makes the primitive's input nonzero for BSR-based backends. It
needs one OR, not a compare, conditional select, and separate zero result.
This is a correctness repair, not a measured speedup over a wrong compiler.

Insertion is deferred until existing index-based rewrites finish and applied
in reverse position order, so it does not invalidate their coordinates.
Tracked source spans are extended with the original select's span. A fourth
Rust test constructs **two CLZ networks in one block**, verifies both OR/CLZ
pairs and their spans, preserves result IDs, and checks pass idempotence.
The runtime count-zero test exercises zero in both the canonical CLZ and CTZ
controls; the CTZ case was already handled correctly by the local fork.

## Valuable salvage: two SQLite-derived failure shapes

### `cmp_select_fusion_stale_cond.c`

The incoming test captures the sorter bug caused by moving a compare beyond
its operands' live ranges. Its adjacency fix is already present locally in
`detect_cmp_select_fusion`; replacing that implementation provides no benefit.
The missing test **does** provide value:

- preserve the four original output cases (`-7 7 1 0`);
- keep `cmp_bytes` externally visible and `noinline`;
- execute all **65,536 first-byte pairs**, second-byte mismatches, equality,
  and zero-length comparisons against an independent scalar expectation;
- fail by exit status, not merely by an explanatory comment.

### `loop_memory_promote_alias_load.c`

The incoming test captures a stale-memory/infinite-loop shape from
`sqlite3FpDecode`. The local loop-promotion pass already contains stronger
alias, must-execute, access-order and exit-value contracts. Keep that pass.
Import the reproducer, prevent inlining, add **210 `(length, retained-prefix)`
cases**, and check both the final count and pointer identity. Correct the
original explanation: after trimming three zeros, `n == 0` stops the loop;
the preceding `x` is not read.

Both SQLite tests and both bit-idiom tests pass GCC ASan+UBSan execution. The
new fast gate runs them at `-O0/-O1/-O2/-O3`. A runtime timeout makes the historical hang
a gate failure. Local and hosted CI invoke the same gate.

### Known cost outside those six kernels: guarded CLZ in `bitops`

A final assembly red-team check of the incoming/common `bitops.c` benchmark
found a **real static cost**, not binary identity: its already-zero-guarded CLZ
now has two extra instructions (`movq` and `orq $1`) before `lzcntl`. The six
identical workload binaries above must not be generalized to this benchmark.
The portable zero-case repair is necessary, but a cheap dominating-nonzero
proof could retain the old sequence for guarded calls. That optimization is
not implemented here. No runtime regression percentage is asserted from static
counts or timing concurrent with CI. This cost is explicitly accepted for the
correctness repair and prioritized in the follow-up, rather than concealed by
a geometric mean. Reproduce by comparing `-O2 -S` output for
`tests/benchmark/programs/bitops.c` with the baseline and submitted compiler.
