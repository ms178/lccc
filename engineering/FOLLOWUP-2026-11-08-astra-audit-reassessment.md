# Astra §13: reassessment against current main

## Scope and evidence standard

Astra measured `8acfe4c`; this review starts at `35a1e23e42e79179e8f218e21f89cebbbb400f8d`. They are not the same tree. The `gcc.c-torture` trunk revision cited in the report is `c94b688a83fc84015c6fab8ab0ff142051598fc8`. The repository runner is a *native differential subset*, not DejaGnu: it handles only some directives, asks GCC whether a case is eligible before testing LCCC, and records skips and reference failures separately. Astra's LCCC-only counts have a different denominator and cannot be subtracted from the differential totals.

For the open questions below, “unverified” means that source reading or earlier documentation is not a fresh execution. This review does not certify the full compiler, close the register-allocator programme, or assert global performance optimality.

## DA-04 changes and limits

The driver now creates its results directory before its own preflight checks, removes stale reports for that architecture before testing binaries, and records specific early failures in `preflight-failure.txt`. It preserves reference/candidate distinction in the advisory warning. The hosted leg publishes a compact per-case annotation only after `torture_evidence.validate` accepts a complete current-schema report; malformed or incomplete reports cannot become summaries. Oversized annotations explicitly state how many case identities were omitted; complete case inventories remain in the report artifact. Tests inject missing and non-executable compiler/linker, missing/mismatched GCC, bad job count, stale reports, reference failures, skips, duplicate rows, unknown statuses and incomplete reports.

A checked-in per-case ratchet now uses complete hosted inventory and provenance annotations rather than Astra's old LCCC-only counts. It checks corpus/target/options, case set, selected-source and bounded local-dependency digests, runner and its support modules, GCC driver, hosted image and a search-environment digest. It retains every skip and unsupported identity and compares phase, return code and a hash of the runner's bounded diagnostic; a fix or changed diagnostic requires explicit review. Reference failures and identity drift fail the comparison. The checked baseline and the rebaseline procedure are in `engineering/evidence/gcc17-torture-baseline/`. The ratchet rejected [run 42535980102](https://github.com/ms178/lccc/actions/runs/42535980102) specifically for the intentional runner hash change; complete annotation comparison showed all outcomes unchanged before rebaselining. Earlier [run 42534755167](https://github.com/ms178/lccc/actions/runs/42534755167) passed the prior ratchet on both ABIs. This workflow is scheduled/on-main/manual, not a mandatory PR check; filtered dispatches are advisory. Neither green nor an unchanged failure means the six compiler cases were fixed.

The baseline is not hermetic: system headers, CRT, binutils, external shared libraries and kernel are not all content-pinned. The local dependency walker covers bounded quoted includes, not every preprocessor dependency form. The GCC 16.2 prefix is now checked against a content/mode tree digest derived from the SHA-256-verified archive **before** its cached driver executes; that does not cover external host inputs. The prior version-and-probes-only policy accepted altered cached auxiliary compiler files; a mutation test rejects that old policy. On this sandbox, five warm-cache prefix-verification samples had a 0.4475 s median versus 0.0019 s for `gcc-16 -dumpfullversion` alone; these measure the integrity-check overhead on one cache state, not compiler or generated-program runtime. A selected-source digest was also previously compared at a nonexistent top-level field; mid-run changes to header-free sources could evade drift detection. Focused mutation tests exercise that and failures while capturing/verifying run identity; those failures now yield incomplete infrastructure reports and exit 2.

A targeted local Python model compared line-offset arithmetic with byte counting for every byte-boundary pair in empty, LF, CRLF, UTF-8 and no-newline strings; an end-boundary `<` mutation was detected by the model. This is not a compiled-Rust mutation test. The Rust boundary/reference test and scope-behavior tests require hosted CI. The branch uses targeted local Python/shell checks only; the user prohibited local CI runs. Full tests and the pinned corpus campaign run on GitHub. Previously documented corpus fixes predate this branch. The measured declaration-speed result above concerns compiler processing time, not the speed of generated programs.
