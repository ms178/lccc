# PR salvage audit against current `ms178/lccc` main

**Audit base:** `a88fb736bfe253c91018b32ea0ba5d4b7dc6057e` (PR #844 merge; `origin/main` at audit time).
**Method:** GitHub REST inventory of PRs 1–847; fetched all 188 unmerged closed PR head refs and compared each PR base→head file list and resulting blob state with the current main tree. Open PR source was inspected separately. PR CI status was queried with `gh pr checks`; no local compiler run is claimed across all 188 historical PR heads (targeted candidate runs are listed separately below). Tree/blob equality is a duplicate/supersession indicator only, not a semantic-equivalence proof. The attached per-PR matrix is reproducible from the recorded base/head IDs on the GitHub PRs.

## Inventory and quantitative results

- **848 total PR records:** 656 merged, 188 closed without merge, 4 open.
- Closed-unmerged tree comparison: **16,807 PR-file occurrences** across the 188 PR diffs, **5,497 distinct paths**; 9,151 occurrences currently have the same path/blob as main and 7,656 differ. These are repeated path appearances across PRs, not unique source changes.
- Of **3,351 source-file occurrences**, 335 match main byte-for-byte and 3,016 differ. 137 PRs have a mixture of matching and different changed paths; 49 have no exact path/blob matches; 1 is byte-identical for every path it changes. This does not prove the semantic feature is absent where files differ—later implementations commonly rewrite the same code.
- No closed-unmerged branch is safe to cherry-pick as a whole based on these metrics. 186/188 have at least one changed path whose current tree state differs from main (one has no tree delta at its recorded base/head); most need rebase and semantic replay against the later implementations.
- Worktree has an **8 GiB active swap**. Orphan-tag payloads `harness-cache-1`, `harness-cache-3`, and `rust-cache-1.97.0` were extracted and their 13 manifest-pinned archive digests and XZ integrity checks passed. GCC 16.2 is available at `/opt/gcc-16/bin/gcc-16`; Rust/Cargo/rustfmt/Clippy 1.97.0 at `/tmp/lccc-rust-1.97`; QEMU 8.2.2 AArch64/RISC-V user emulators were rehydrated at `/tmp/lccc-tools/bin`. This is the published Bookworm GCC cache, not a freshly installed Debian Sid toolchain. ICX 2026.2 is not cached locally; the authenticated provisioner was attempted but Intel PPA TLS terminated (EOF) under this harness network policy. Hosted CI can still provide an exact-head ICX receipt.

## Open PRs: semantic disposition

### PR #847 — driver option contracts, freestanding/builtin behavior, vectorizer control

- **Head:** `cbf72a16a34073906dcb10161027f9f860a99873`; 27 files, +4,679/−3,404 by PR metadata. GitHub reports 14 successful checks and the named candidate semantic/performance audit skipped. GitHub currently marks it **CONFLICTING** against main. `git merge-tree` finds conflicts in `src/driver/cli.rs`, `src/frontend/sema/analysis.rs`, and `engineering/archive/BACKLOG-2026-10-16.md`.
- **Worth salvaging:** the `-fno-tree-vectorize` implementation is a real missing contract on main (main currently warns for unsupported options and does not disable those automatic vectorizers); the driver’s explicit option classification removes silent fallbacks; and blanket `-fno-builtin`/`-ffreestanding` must suppress ordinary hosted-library folds throughout sema, IR lowering, math simplification, and purity inference. The explicit propagation instead of ambient thread-local state is the better design. The PR also fixes embedded-NUL `strlen` folding. GCC 12.2 locally confirms the behavior: hosted `strlen("ab\0cd")` folds to 2; under `-fno-builtin`/`-ffreestanding`, the ordinary call remains, while explicit `__builtin_strlen` still folds to 2; `__STDC_HOSTED__` follows last hosted/freestanding option. This is GCC 12 evidence, not GCC 16 validation. On this branch I also fixed the narrow embedded-NUL length defect in both the front-end constant evaluator and post-inline IR `strlen` folding through one shared helper, with a unit regression for `"ab\\0cd"` and a plain-string positive control. The two focused Rust test groups have now run (2 enum-scope and 2 string-length tests passed each); the end-to-end embedded-NUL contract also passed with GCC 16.2 at `-O0`/`-O2`, including the `-O2` no-`strlen`-call assertion.
- **Red-team caveat:** the PR threads a blanket `no_builtins: bool` and refuses `-fno-builtin-<name>`. Main already has a per-name `BuiltinPolicy` for libcall synthesis. The best integration should either explicitly refuse per-name options until their entire fold path is wired, or preferably thread the existing policy object through sema/IR/pass consumers so `-fno-builtin-strlen` suppresses every relevant fold without losing supported per-name behavior. Do not merge the boolean alongside the policy and leave two sources of truth. Preserve main’s historical backlog archive; do not accept the PR’s stale documentation replacement as current history.
- **Verdict:** high-value changes, but rebase/resolve the two source conflicts deliberately, preserve archival records, and add tests for per-name-vs-blanket interactions. Do not cherry-pick the PR wholesale or claim performance gains; its benchmark lane is a regression gate, not a measured speedup.

### PR #848 — `ext_vector_type` padded layout and by-value ABI

- **Exact audited head:** `2285e0d59576599038179ae8594d8d55f9f8a5e7`; 52 files, +3,687/−539. This PR was not in the earlier 847-record census. It is mergeable but `UNSTABLE`, not green. Latest hosted checks: Clippy, MSRV, build/unit, GCC16/Rust1.99, Frontend/ABI, Codegen/runtime, complete benchmark corpus, and ICX pass. Four failures remain: Assertion-enabled corpus, SSA corpus, Assembler/linker, and Test Suite.
- **High-value design intent — agree:** keeping Clang `ext_vector_type(N)` distinct from GCC `vector_size(bytes)` is the right type-system boundary. A first-class descriptor separating logical lanes from padded object storage/alignment and bool bit-packing is materially safer than inferring lanes from byte count. A shared initializer planner for arrays of ext-vector leaves is a defensible centralization point. Layout, global-object, and mixed-compiler by-value tests are the right categories, and the current main tree's single `CType::Vector(elem, bytes)` cannot represent these distinctions without reintroducing ambiguity.
- **Do not accept the current PR wholesale — direct red-team evidence:** the exact-head hosted run (39037128336) marks the normal and debug regression corpora failed because `vec_incdec_elementwise` compiles but aborts at runtime (`rc=-6`); the SSA run reports the same regression. This contradicts the PR's own latest fix claim that `vector_size` codegen is preserved. Separately, the assembler/linker annotation reports **48** runtime-kernel vector copies against the newly lowered budget of **44**. I independently built the PR source at `ce7a8ec` (compiler code unchanged by the subsequent CI-only annotation commit) and reran `check_vector_copy_elimination.sh` with GCC 16.2: it likewise reports 48 > 44 (46 checks pass, one fails). This is not permission to raise the threshold; the claimed measured 42 is not reproduced and the intended code-quality improvement must be explained and demonstrated before accepting the ratchet change.
- **ABI evidence and remaining gap:** latest hosted Frontend/ABI is green. Locally, with the PR-built compiler, LCCC→LCCC ABI runtime cases passed for m64 and m32 at O0/O1/O2; its two gates' layout/runtime and emitted object-size/alignment tests passed for both widths. Local Clang was unavailable, so local cross-compiler cases were skipped; hosted CI is the evidence for those mixed legs. However `check_ext_vector_abi.sh` deliberately excludes all mixed-compiler `f64x1` cases: its own comments say Clang passes/returns that type in MEMORY while LCCC uses `%xmm0`. That is a known interop mismatch, not proof of a Clang oracle defect. Since this feature promises Clang extension ABI compatibility, do not count the same-compiler legs as closure of this shape; implement the Clang carrier or explicitly narrow the documented support contract. The script also makes Clang and i686 availability optional unless environment variables are set; hosted wiring should force both prerequisites rather than permit silent skips.
- **Architecture/design cautions:** the i686 path overloads SysV `EightbyteClass::NoClass` as a sentinel for stack-passed scalarized ext-vector lanes and reuses INTEGER-class arrays to identify i686 multi-GP return bundles. This couples i686 mechanics to a different ABI's classification vocabulary. Prefer an explicit target-neutral/target-specific ABI carrier enum or lane-passing descriptor, and prove ordinary scalars/aggregates can never collide with the sentinel. Review all fixed/variadic, direct/indirect, return/call, optimization-level, and 1–4-lane/packed-bool cases before treating the marker plumbing as complete.
- **Verdict:** salvage the distinct ext-vector representation and its focused layout/initializer/ABI tests, but only as a set of small, separable patches after the vector-size abort is fixed, the 48-copy discrepancy is resolved without weakening measurement, and the `f64x1` interop exclusion is either closed or explicitly accepted as a limitation. Current main remains preferable to this head as a merge candidate because it is stable and CI-green; PR #848 has valuable semantics but currently fails correctness and code-quality gates. No performance superiority is established: the relevant local gate is static copy count, not controlled wall-time A/B.

## Decision and remaining acceptance work

1. **Current main is the best integration base**; it contains extensive later correctness evolution and the upstream CI receipt, but this audit does not prove it is defect-free or faster than GCC/Clang/ICX.
2. **Do not merge or cherry-pick #829.** **Do not merge #845** until the known hosted/local gate-parity gap and current failing hosted lanes are resolved; its earlier snapshot-script regression has been reverted upstream. Salvage narrow compiler fixes with focused tests. **Salvage #847’s semantic intent**, but compose it with the existing `BuiltinPolicy`, preserve archives, and add per-name/blanket policy tests before rebase.
3. This workspace’s harness duplicate-trace fix, embedded-NUL `strlen` correction, enum scope/identity correction, and backlog/archive reconciliation are committed as `9908eef69` on the PR #850 branch. Targeted Rust tests pass (2 enum-scope and 2 string-length); enum GCC16 differential and embedded-NUL tests pass, including no `strlen` call in -O2 assembly. CI/local parity passes (264 commands, 25 invocation contracts, 2 asm-diff gates); rustfmt, MSRV, strict Clippy, and `git diff --check` pass. The negative enum-pointer control is generated ephemerally because the broad positive corpus compiles every checked-in `.c` fixture; the full compile-only regression corpus passes **985/985**.
4. After rehydrating QEMU from the hash-verified `harness-cache-3`, the required `scripts/ci_local.sh --fast` completed **292 passed, 0 failed, 6 skipped** on this working tree (Debian 12 host, cached GCC 16.2, Rust 1.97.0, active 8 GiB swap). 5. **Open PR dispositions refreshed:** #847 is conflicting and still skips its named candidate audit; #845 is unstable with assembler/linker and full benchmark failures; #829 is conflicting with Test Suite failure and its named Callgrind comparisons skipped; #848 is unstable with the four failures documented above. 6. This is not yet a full semantic adjudication of every historical PR.
