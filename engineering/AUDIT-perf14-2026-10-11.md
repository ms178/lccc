## Build failure and previous select failure

PR #799 fails with E0631: forwarding `&mut |op|` to a generic visitor prevents
contextual inference of its borrowed argument. Pass the closure directly,
matching the canonical visitor's existing callers; no operand clone, adapter,
allocation or changed escape semantics is needed. Both operand-reference and
bare-value visitor paths now have a targeted derived-root escape contract.

The earlier select failure was separate; negative-test diagnostics were intentional.

Using existing binaries, disabling only `intbounds` restores the ASCII-fold
assembly byte-for-byte to pristine upstream output. The bound pass changes a
boolean's signed widening to unsigned widening. This exposes ordinary register
copies after normalization; the flag-fusion matcher recognized byte extensions
but not those copies. The resulting `setbe; ...; test; cmovne` remains unfused.

The repair tracks normalized 0/1 carriers through full 32/64-bit copies. Every
deleted destination still needs a deadness proof; intervening flag effects,
live copies, partial writes, labels and cmov operands remain barriers. A raw
`setcc` proves only one byte, not zero upper bits. Wide tests without
normalization and high-byte spellings are explicitly rejected.

The gate itself also had a false control: it set an unimplemented variable on
the generated executable, not on compilation. It now uses the implemented
`CCC_PEEPHOLE_SKIP=setcc_cmov` compiler control and requires the unfused assembly
in that arm. Offline protocol tests reject a compiler that ignores the control.

## Correctness fixes, including bugs present on upstream main

- **Displaced pointer aliases:** DSE compared offsets belonging to different
  roots. In `*p=1; r=*(q+1); *p=2`, a valid caller can make `q+1 == p`.
  Distinct numeric offsets do not prove disjoint storage. Range comparisons now
  require the same root; overflow makes a proof unknown, not saturated.
- **Conditional effects:** range/phi folding could delete a short-circuit block
  containing an effect. Its purity and escaping-definition checks now reject
  stores, calls, asm, volatile reads and unmodelled operations. Integer range
  folding is separate from the new producer-bound analysis, not a rewrite to
  conform to that analysis.
- **Declared global aliases:** a function-local DSE map cannot assume different
  symbol names mean different objects. Existing main and reviewed binaries both
  remove the observable first store in the recorded alias probe when other
  canonicalizers are disabled; disabling DSE restores it. Distinct global names
  now conservatively may alias. Same-root interval precision is retained.
- **Mutable pointer webs:** resolution rejects a multi-defined value and any
  chain depending on it, rather than disabling DSE for unrelated values.
  Removing the whole-function guard alone is insufficient: unresolved reads
  must not be allowed to observe an allegedly closed alloca. Escape analysis
  therefore follows every defining edge backwards, independent of block order,
  opening all roots reachable from mutable pointers or escaping uses.

Reproducers: `tests/regression/memory_value_forwarding.c`,
`tests/regression/adjacent_membership.c`, `tests/regression/dse_global_alias.c`,
and the DSE/range unit tests. Escape tests include valid non-topological block
storage and an independent alloca that must still benefit from elimination.

### Cross-vendor disagreement is evidence, not authority

The GNU alias probe declares the attribute in the same translation unit and
uses matching types, sizes and alignment, as required by the
[GNU alias contract](https://gcc.gnu.org/onlinedocs/gcc/Common-Attributes.html#index-alias).
It must observe 17 before the final store of 29. On Compiler Explorer at
`-O2 -march=x86-64-v3 -fwrapv`, Clang 23.1 and ICX returned `17 29`; GCC 16.2
and ICC 2021.10 returned `0 29` and failed the fixture's self-check. Unoptimized
GCC and ICC controls both returned `17 29`. ICX is a moving channel, not a
numerically pinned release. All results, including disagreements, are retained
in `evidence/global-alias-oracles.json`.

The regression gate uses a GCC unoptimized reference only for this fixture and
also asserts its exact expected output at both widths. Other fixtures retain
their optimized references. Candidate optimization levels and pass-disabled
arms are unchanged or expanded. This is not evidence that the then-unbuilt
corrective LCCC source passes all checks, nor a blanket claim of superiority over vendors.

## Shared proofs and structural changes retained

Exact-type, single-definition store-to-load forwarding reuses the existing
address/alias proof. Unknown effects invalidate availability; narrow stores do
not become untyped wide copies. Late DSE consumes newly exposed dead stores.
Late cleanup retains shared proofs in normal builds. Early placement is opt-in:
`CCC_ENABLE_PREINLINE_MEMORY=1`; existing disable controls still dominate.
`CCC_TIME_PREINLINE_MEMORY=1` reports stage cost. See
`evidence/preinline-placement.json`: smaller static code did not mean less work.

Producer bounds describe a known low-bit width, not guessed register contents.
Typed consumers may truncate that domain, but may not invent upper bits when
widening. Cast normalization stays explicit. Cycles, mutable definitions,
unsupported types, negative signed carriers and invalid shifts fail closed.
The analysis does not confuse an upper bound with a known-bit mask for OR.

Switch bounds are recomputed after phi lowering and cleared per function.
Only a proven zero-based, in-range selector removes the outer comparison.
Normalization and default entries for holes remain. New emitter tests cover
signed/unsigned normalization, PIC/absolute/kernel tables, holes, missing facts,
width mismatches, out-of-range bounds and nonzero minima. Existing reviewed
compiler assembly is **88 instructions with the analysis disabled versus 86
with it enabled**, removing one comparison and one branch. That is a static
result, not a timing result; see `evidence/review-diagnostics.json`.

Vector addresses are canonicalized before allocation so liveness sees the
actual base, rather than inventing hidden register uses afterward. Composed
x86 displacements are checked. Cycles, mutable bases, malformed forms and
unrepresentable offsets are refused. Direct object slots remain distinct from
pointer payloads and over-aligned objects. Other backends are not enabled.

## Additional address and measurement findings

- Fast CI exposed a per-function environment read in switch-bound analysis.
  Resolve permission once per module, opt in only audited emitters, and keep
  the analysis pure. The environment-read budget stays unchanged at 153.

- Large vector displacements were emitted as if x86 SIB accepted signed i64.
  Ordinary loads/stores now stage oversized offsets with flag-neutral LEA/MOV
  using reserved scratch registers. Encodable disp32 accesses gain no work.
  Deferred loads refuse the large form: scratch addresses cannot survive until
  an arbitrary later consumer. Hoisted FMA shares one adjusted index across
  its two streams and store, preserving every allocated input home.
- The hoisted FMA emitter also peeled an Add after allocation, creating hidden
  uses and ignoring narrow-add wrap semantics. Safe I64/U64 additions now become
  explicit intrinsic arguments in the IR pass before liveness; mutable or
  narrow/unknown carriers are refused. The emitter consumes those arguments.
- The legacy Callgrind shell driver could continue after build/instrumentation
  failure and report stdout mismatches without failing. It now rejects failed
  execution, stale/missing/invalid counters, instrumentation divergence and empty
  selection before publication. Three protocol tests cover eleven scenarios.
- New bounds coverage enumerates 524288 byte/mask/shift combinations and checks
  signed extension, arithmetic shifts and rewrite idempotence. Additional
  emitter contracts cover signed disp32 endpoints, i64 extremes, deferred
  addressing, allocated/spilled FMA operands and forbidden late reconstruction.

ISA basis: Intel SDM 325383-093US (September 2026), addressing section 2.2 and
MOV/LEA/SETcc/CMOVcc/SAR entries; AMD APM 24594 revision 3.38 (July 2026),
addressing and corresponding instruction entries. Download identities and
source-access limitations belong in the delivery review. Neither manual proves
14700KF runtime performance; no AVX-512 or speculative dereference is introduced.

## Measurement integrity and known adverse results

The historical measurements below predate the upstream per-CPU integration and
the corrective source. Do not attribute upstream changes to this patch.

| Workload | Historical minimum / low-three ratio, candidate over baseline | Interpretation |
|---|---:|---|
| SipHash | 0.787 / 0.787 | Large observed reduction, not a current-head guarantee. |
| XML | 0.994 / 0.995 | Too small to establish a robust native win. |
| nbody, default linkage | 1.003 / 1.001 | Slight adverse sample, not a win. |
| SHA-256 | 0.991 / 0.994 | Native sample improved slightly; simulated Ir regressed about 0.028%. |
| TLS | 0.981 / 0.984 | Short workload; further evidence needed. |
| struct_copy | 1.023 / 1.006 | Minimum regressed 2.3%; low-three regressed 0.6%. |

An alternate matched libm configuration gave a much larger nbody improvement;
that sensitivity prevents a universal speedup claim. Callgrind Ir is simulated
instruction work, not cycles or PMU evidence. Raw samples and adverse results
remain in the memory-dataflow and vector-address JSON evidence. Their renames
are byte-preserving and recorded in `evidence/retained-evidence-sha256.json`.

The comparison harness also places libraries after the source/object while
preserving linker-option order: shared flags alone do not prevent `--as-needed`
from discarding an early library. This repair has offline command contracts;
a real Valgrind own-object smoke now passes; absent second profiles fail closed.

Matmul, Mandelbrot, hash table, SQLite varint, strlen, memcmp and fannkuch have no
established gains from this work. Count-bound changes need fresh zstd results.
**The all14 performance program is not complete.** No correctness expectation is weakened.
