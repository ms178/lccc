## Correctness findings that block optimization unless repaired

### DSE: offsets in different coordinate systems

```
*p = 1;
int observed = q[2];
*p = 2;
```

With `q == p - 2` (integer pointers), the middle read observes the first store.
PR795 instead returned the previous value (`9 2` versus GCC's `1 2`). Relative
byte offsets cannot prove disjointness when the roots may be displaced aliases.
DSE now compares ranges only for equal roots; a potentially aliasing different
root invalidates the pending overwrite proof. Same-root disjoint-field
elimination remains enabled and is tested over overlapping and adjacent ranges.

The same audit replaces saturating offset addition and unchecked range endpoints
with fail-closed arithmetic, rejects unrepresentable 128-bit offsets (the IR's
`to_i64` deliberately truncates, so it is NOT a checked conversion), guards
non-SSA definitions, and resolves pointer cycles iteratively. Segment-relative
accesses are opaque, not default-address-space disjointness proofs.

### Phi range folding: deleting a conditional side effect

```
return x >= 10 && (++volatile_counter, x <= 20);
```

At `x=15`, PR795 returns true but never increments the counter. The old fold
verified uses of the second comparison but not the purity of its whole block.
The check arm must contain only the comparison and integer casts; every local
definition's external uses are checked, including terminators. A store, call,
asm or other computation disqualifies the candidate. Existing sibling-phi and
canonical-CFG predecessor proofs are retained, not bypassed for the new cases.

## Structural changes

* Exact producer/store/load-type SSA values seed memory availability. Unrelated
  roots still may alias; unknown writes, address spaces, volatile accesses,
  truncating stores and multi-def values fail closed. Transitive substitutions
  are flattened before the one-step operand visitors; debug spans stay aligned.
* The same memory proof runs before inlining cost analysis and in late cleanup.
  Exposed dead stores use DSE, not a second ad-hoc store deletion algorithm.
  This allows costing actual field-update dataflow instead of frontend reloads.
* Adjacent equality OR / inequality AND sets reuse the shared unsigned-bias
  range planner with the opposite polarity to bound-check conjunctions.
* A short-circuit pair at the tail of a multi-predecessor phi is folded by
  changing only its incoming edge. Other arms and the phi remain; a two-arm
  proof must not be used to replace a larger join globally. This is the actual
  IR form seen in the XML '-' / '.' classifier, not merely a source analogy.
* Named recovery checkpoints are retained by default. Explicit rolling pruning
  now requires both a positive `LCCC_SNAPSHOT_KEEP` and
  `LCCC_SNAPSHOT_ALLOW_PRUNE=1`. A newer patch against a different base cannot
  reconstruct a historical checkpoint. Budget pressure is not permission to
  silently delete history.

## Rejected shortcut and remaining gaps

Enabling `CCC_FP_EXTRACT_HOMES` still fails the adverse nbody link configuration:
the no-`-lm` probe regressed while the `-lm` probe improved. It remains opt-in.
Attempts to fix `.data` through the internal linker did not move the symbol;
those runs are explicitly **not** matched-layout controls. An external link
with verified ELF addresses is needed before making a layout-causal claim.

Matmul already contains four YMM FMA updates per unrolled inner iteration.
Mandelbrot repeats products across iteration boundaries; GCC carries one square.
TLS already benefits from distance-one memory forwarding but retains address,
callee-save and pointer-slot overhead. These are different structural problems;
none is solved by reporting the SipHash win as a geomean. No claim that all 14
are improved, or that LCCC universally outperforms the four oracles, is warranted.

## Vector addresses: representation before register allocation

V3/V4 add `vec_addr_fold`, an x86-64-only, late SSA canonicalization. The shared
alias descriptor identifies register-vector memory argument shapes; constant
GEP chains become checked disp32 operands. Cyclic/multi-defined bases, malformed
arity, non-integer or unrepresentable offsets and overflow fail closed. Argument-
address stores remain effectful when their redundant legacy `dest_ptr` is
removed. DCE removes the now-unused pointer definitions **before** register
allocation, rather than secretly rematerializing an unmodelled address afterward.
`CCC_DISABLE_PASSES=vecaddr` provides a same-compiler control.

Nbody's nine long-lived constant-offset pointer homes disappear. Its static
whole-TU count is 302 → 270 instructions, stack references 30 → 11, and frame
reservation 136 → 56 bytes. Simulated whole-program Ir falls 1.89%. In the
alternate `-Wl,--no-as-needed -lm` link, V4 versus V2 measured 382.97 → 321.82 ms
minimum (16.0% lower, low-three ratio 0.843). Without that link variation, the
latest screen was effectively flat/slightly adverse: 330.66 → 331.79 ms,
low-three ratio 1.001. **This is not a layout-independent 16% speedup.** Fewer
pointer reloads are visible; how much of the timing change comes from frame or
code layout has not been isolated. Unlike the rejected FP-homing switch, this
candidate did not reproduce its large adverse no-libm regression.

The emitter also handles ordinary constant-offset stack objects directly,
without routing their address through a scratch GPR. Pointer/payload slots and
runtime-overaligned objects are explicitly excluded. Constant index plus
intrinsic displacement is checked as a whole before using disp32, including
128-bit constant conversion and overflow. The fallback retains register indexing
when the composed displacement does not fit; this is not a claim to have audited
all possible malformed intrinsic displacement arguments.

V3 and V4 produce **byte-identical binaries for all 43 existing benchmark
sources** at the native-screen flags. Therefore differences between their
screens are noise, not wins from the direct-stack emitter refinement. That
refinement is backed by dedicated contracts, not a benchmark-speed claim.

V4's 43-case Callgrind output comparison passed completely. SHA-256's Ir ratio
is **1.000276958**, a small instruction regression, not a hidden win; its static
count nevertheless falls 279 → 272 and its native low-three changes are small.
The latest struct_copy minimum worsened 2.3% (low-three +0.6%), after earlier
flat screens of the identical candidate binary. Preserve that adverse sample;
there is no demonstrated native struct_copy gain. SipHash remains the strong
native result: 476.47 → 374.99 ms (21.3% lower) in the final screen so far.

`evidence/perf14-v4-2026-10-11.json` embeds raw samples, both link configurations,
source/compiler/executable hashes, all 43 simulated profiles' summaries and all
14 static comparisons. Only six corpus binaries differ from PR795; among the
requested 14, only nbody, SipHash, XML, TLS and SHA-256 differ. Thirty-seven of
the full 43 are byte-identical. None of their timing fluctuations is an earned
optimization.

### Correctness and measurement contracts added with V4

* Seven IR tests cover chained/negative offsets, variable indices, disp32
  boundaries, I128 truncation, overflow, cycles/multi-defs, malformed arguments,
  idempotence and effectful stores surviving DCE.
* Three emitter tests cover checked displacement composition, RBP/RSP addressing
  and rejection of pointer/payload/runtime-overaligned slots.
* `vector_address_folding.c` exercises ordinary, aligned and global objects,
  variable lengths 0..17, repeated field updates, tail guards and an independent
  volatile reference. The common gate now runs all three regressions at O0..O3
  on baseline x86-64, x86-64-v3 and i686, plus disabled-pass controls.
* The library run passed **4323 tests, 0 failed, 7 ignored**. The C matrix passed.
  All three C regressions passed all four CE execution oracles (12 comparisons),
  with live versions GCC16.2, Clang23.1.0, ICC2021.10.0 and ICX `(latest)`.
* `perf_ab.py` no longer silently adds libm to just one vendor arm. Automatic
  linkage is shared and reported; existing LCCC-only defaults stay unchanged.
  Offline tests pin symmetry, explicit flags and compiler-basename selection.
* The local CE helper also retains its existing `binary=None` caller contract;
  both that default and explicit frozen binaries have offline tests.

These are earned component results, **not** a replacement for a fresh complete

### Integer-bounds checkpoint (work in progress; no fast receipt yet)

The first width-qualified shared bounds implementation passed nine Rust tests
and all 52 configurations of the four-fixture executed regression matrix
(O0/O1/O2/O3, default/v3 x86-64, i686, and disabled passes). A freshly built
pristine PR797 compiler is retained for comparisons. The count probe exposed
an important missed opportunity: optimized IR feeds a U64 count producer
directly into an I32 shift, without an intervening Cast. Requiring identical
producer/consumer widths safely declines this shape, so its assembly is still
unchanged. This is not a claimed count-range performance win. A follow-up must
model explicit truncation by typed consumers, without guessing upper bits when
widening a narrow carrier.

PR797's previously unregistered per-CPU pointer benchmark is now registered,
with a bounded 1000-pass Callgrind size; the corpus now has 44 cases. Unsupported
GS exits nonzero instead of publishing a fake successful empty timing. GCC and
the pristine PR797 compiler both produced `percpu-ptr-walk: 527104000` at this
size; a Valgrind smoke run executed the actual GS workload. Five corpus-screen
contracts pass. The 43-case measurements above are historical, not 44-case data.
