# Upstream rebase and diagnostic audit, 2026-10-31

The upstream main branch advanced to `38a2c1bd6edf5e6b54fab279d69034e2c5d48574`, merging PR 1037 and its follow-up parser, assembler, CI, and diagnostics work. The PR head had the same tree as the earlier S19 snapshot, so the local continuation was rebased from S20 onward rather than replaying those already-merged changes. Obsolete duplicate CI rewiring and an already-reverted preprocessor candidate were dropped. The only rebase conflict was in the division-by-zero regression: both upstream's value-folding cases and the local overflow tests were retained. The upstream parser, assembler, fixture renames, and other changes remain intact.

After rebasing, the compiler was built with the required fastbuild profile, O1 and two jobs. The pinned GCC 16.2 32/64-bit division diagnostic matrix, preprocessor splice regression, upstream GCC statement-expression tail matrix, documentation links, CI gate parity, shard partition, lane plan and rustfmt checks passed. A fresh adversarial audit found a missing diagnostic in the newly merged truth folder: a non-ICE expression such as a selected value 256 narrowed to unsigned char zero, although its pre-cast truth value was nonzero. GCC 16.2 diagnosed integer division by that result; LCCC did not. The old implementation's claim that every integer cast preserves truth was incorrect.

The diagnostic-only cast fold now tries the typed, target-width constant evaluator with the ordinary const-value cache disabled and evaluated signed overflow checked. It retains a proven false result, but only propagates a nonzero truth through a conversion when it is boolean, the source is a known 0/1 logical or comparison result, or an integer conversion is not narrowing. Unknown cases remain unknown; this does not affect operand elision or generated code. Eleven named GCC controls and a deterministic 960-comparison cast matrix were added to the existing 680-comparison arithmetic matrix, bringing it to 1,640 comparisons across both x86 modes; all passed. These tests do not establish exhaustive GCC compatibility.

A follow-up red-team audit separated GCC's treatment of an overflowing ICE as a divisor value from its use for suppressing branch diagnostics. For the former, GCC can use the wrapped value to emit division-by-zero; for the latter, direct overflow prevents suppression, but a conditional result carries the selected arm's overflow state rather than its condition's. Five named controls and a 780-comparison audit over direct, conditional and short-circuit shapes on m32/m64 with and without `-fwrapv` passed against GCC 16.2. The value-only fold is not used for operand elision. This describes observed GCC behavior on the tested cases, not a proof of complete GCC equivalence.

The 2,420-comparison diagnostic matrix was then batched into chunks of 40 uniquely named one-line functions. A fail-closed parser rejects crashes, truncated output, out-of-range or unrelated errors, mismatched exit status, and unexpected stdout; its negative fixtures run on every invocation. A validation mode reran every case separately for both compilers and confirmed every batched verdict against its isolated counterpart (2,420 comparisons, zero mismatches). On this host the unchanged 2,420-case isolated gate took 33.30 s, the batched matrix took 1.06 s, and the complete batched gate took 2.57 s; these are local elapsed measurements, not hosted-run predictions. The CI lane plan now records the latter measurement, and its balance and shard partition checks pass.

This is an ungated interim snapshot: the rebased full fast local CI, rustfmt/clippy gates within it, representative performance measurements, complete kernel image, and real QEMU boot remain to be completed. AArch64 and RISC-V binutils and qemu-user are installed, and GCC multilib and pinned GCC 16.2 m32 execution were verified. Debian's cross-GCC package conflicts with the gcc-multilib metapackage; do not remove multilib silently to install it. Cross compiler provisioning remains outstanding. Hosted CI status on the new branch has not been claimed.
