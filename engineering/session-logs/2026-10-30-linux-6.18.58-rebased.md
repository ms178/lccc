## Compiler changes and focused validation

The initial Linux failure was an immediate-only inline-asm constraint checked
before GCC-style constant propagation/inlining. The follow-up exposed two
additional shapes: `__builtin_constant_p`/`__builtin_clz*` constant trees, and
local `__auto_type __flags` values in x86 `WARN`/BUG macros. Linux also uses GNU
named tied operands such as `"[sum]"`, which the parser's x86 constraint gate
had incorrectly rejected.

The patch now:

1. recognizes the relevant constant builtin and conditional-expression shapes
   during asm constness classification;
2. defers only immediate-operand constness checks in the normal code-generation
   path until optimized IR, then rejects any immediate-only input still
   represented by a runtime value (preventing the backend's zero placeholder
   from becoming a silent miscompile);
3. leaves `-fsyntax-only` on its parser-time diagnostics path;
4. accepts GNU named matching constraints; and
5. covers valid constant/local/always-inline operands and dynamic operands in
   `tests/regression/check_asm_operand_diagnostics.sh`.
