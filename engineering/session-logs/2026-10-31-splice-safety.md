# Translation-phase safety audit, 2026-10-31

The S22 full defconfig build reached 1,078 target compile commands before Linux NFS callback XDR exposed a retained splice break on a physical line that began inside a multiline comment in a directive. An initial streaming-lexer candidate fixed that object, but was rejected because it mistook a C23 digit separator split across a splice for a character literal and then missed a real comment. A separate adversarial case exposed an older silent miscompile where a string escape immediately before a splice applies to the next line's quote; retaining a subsequent break inserted newlines into the string.

A file-wide conservative guard passed the runtime examples but failed a focused Rust test: an ordinary safe splice after an unrelated comment moved its tail token from physical line 3 column 2 to line 2 column 15. That candidate was reverted rather than weakening the test.

The replacement retains phase-2 lexical state across physical lines, including comment delimiters, literal escapes and directive status across a real newline inside a comment. A phase-2 byte stream supplies C23 digit-separator and digraph lookaround across splices. An independent safety check is added to the existing break-retention conditions, so ordinary safe splices still preserve source positions. This is a correctness-first implementation, not a proof that all preprocessing cases are covered.

The standalone regression runs GCC 16.2 and LCCC on both x86 modes at O0/O2. It covers the directive/comment pattern, an opener formed over multiple splices with no adjacent raw opener, C23 separators split on either side, line numbering, an escaped-quote string's complete bytes, a digraph split across a splice, and directives continuing after the comment closes. The compiler passed that matrix; all 21 focused Rust physical-line tests passed on the previous revision, including the position test that rejected the file-wide candidate. The actual patched Linux 6.18.58 NFS callback XDR object compiled with LCCC and real objtool; GCC was used only as a test oracle and for host tools.

A subsequent adversarial position check exposed another existing defect: after a C23 separator split across a splice, an unrelated undeclared identifier on physical line 3 column 2 was diagnosed at line 1 column 16. The regression was first run against the previous compiler and failed as expected. The existing splice-state scan now checks separators in the complete phase-2 byte stream rather than only the current physical part; the new compiler reports line 3 column 2 and passes the expanded GCC differential script. Its targeted Rust unit suite is being rerun before final gating.

A preliminary 12,000-splice synthetic preprocessing sample with a concurrent Rust test build gave medians of 0.0252 s before and 0.0346 s after. It is short, noisy, and not representative; it does not establish a general slowdown or performance win. The additional full source scan and temporary phase-2 buffer need broader memory and performance measurement. The splice-state scanner remains an additional conservative guard; source-position behavior outside these cases deserves further adversarial testing.

At this interim snapshot the final-tree full `ci_local.sh --fast` pass was not complete. The preceding S23 run reached 107 successful gates with zero failures before being intentionally stopped to validate this fix. An earlier run was stopped after the local oracle verifier failed because the Clang executable was missing from PATH; adding the already-installed pinned Clang 23.1.4 made that verifier pass on the next run. No post-fix hosted PR run, full kernel image, boot-size result, or real QEMU boot has been observed. This snapshot is ungated and is not a perfected delivery.
