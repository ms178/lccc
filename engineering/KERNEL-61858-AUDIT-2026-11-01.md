## Confirmed full-build blocker

The full defconfig build reached `arch/x86/kernel/cpu/common.c`, then refused
fourteen Microsoft-x64-ABI declarations in `include/linux/efi.h` (runtime
service pointer fields and the ACPI PRM callback type). This is the existing
fail-closed ABI guard, not an excuse to select the SysV convention silently.
The build was stopped after recording the failure. EFI remains enabled and
`CCC_ALLOW_UNSUPPORTED_ABI` is not used. The EFI stub also defines an actual
`__efiapi efi_pe_entry`; accepting unused annotations alone would not implement
this ABI or make a correct full image. Proper function-type preservation,
caller and callee lowering, stack/shadow-space rules, and register-preservation
support are required before claiming this blocker fixed.

## Changes under validation

1. `build_kernel_boot.sh` now respects HOSTCC for its optional mkcpustr host
   generator instead of hard-coding gcc. Target compilation remains LCCC-only.
2. The defconfig QEMU smoke gate now also requires an LCCC kernel banner;
   the fake-QEMU verdict test rejects an otherwise valid non-LCCC banner.
3. Implement `-fmin-function-alignment=N` as a hard floor in shared function
   placement, rather than treating it as an ignored optimization hint. The
   floor survives `aligned(1)`, cold functions, `-Os`, function sections and
   patchable entry placement. Non-power-of-two values round **down**, matching
   measured GCC 16.2 behavior (3 -> 2, 17 -> 16); 0/1 disable the floor, repeated
   values are last-wins, and malformed/out-of-range arguments are refused.
   Only tiny non-kernel C option probes were compiled with GCC to establish
   that flag contract. Existing no-minimum attribute precedence is retained.
4. A hosted staged kernel job captures preparation, boot-size, full build and
   QEMU evidence, and surfaces failures through Checks annotations. Host package
   exports are opt-in (PR label or manual input), not repeated by every push.
   GitHub-only transport uses unreferenced content-addressed blobs, complete
   part manifests and SHA256 checks; no binary artifacts enter branch history.

## Follow-up: compiler invalidation and measurement regression

The alignment-enabled compiler built successfully (fastbuild, 1m39s), SHA256
`71bb38a32f6ef456fd7834ad71e416ba9d51f1c6915f405a0a04ea5c9d8753da`.
Small standalone `-S` probes verified the hard minimum on x86-64, i686, ARM
and RISC-V. The complete alignment-definition regression is x86-64-specific
(its no-option control expects that target's 16-byte default); it is not a
cross-target default-alignment oracle.

Fresh preparation exposed a real fast-path defect: compiler invalidation's
Kbuild `clean` removes boot-generated canaries, but `make prepare` does not
recreate all of them. Preparation previously published a new compiler stamp
and returned success with `capflags.c` / `cpustr.h` absent. The shared boot-header
helper now restores missing generated files in both preparation paths and checks
**all** canaries before publishing the stamp. Existing real Kbuild outputs are
not overwritten; damaged-tree and source/config/patch provenance guards remain.
Regression `check_kernel_provenance.py` now actually deletes these files in its
mock clean and checks recovery, tool selection, and unchanged stamps after
Kconfig or host-generator failure. Sequencing keeps `errexit` active inside
preparation rather than masking failures with an intermediate `&&` call.

Preparation also now explicitly passes `CC=lccc LD=lccc-ld AS=lccc`, including
Kconfig probes. Otherwise system-linker detection could change
`CONFIG_LD_VERSION` before the full harness switched back to lccc-ld.
Two real clean/reprepare cycles with these explicit tools passed. The original
actual-default-config SHA256 above is restored exactly, with EFI, BORE,
SCHED_CACHE, CACHY and stack initialization still enabled. The subsequent
boot-only gate again passed **31024 bytes**, 24-object ISA audit and GNU-linker
byte parity, with the same `setup.bin` SHA256 recorded above.

Hosted CI run `41318728339` found a measurement bug in the newly extended
alignment regression: its reader discarded alignment at the zero-byte `.LPFE`
alias emitted for patchable entry. The reader now retains placement through
that alias, but resets across sections and instructions. Synthetic negative
controls verify intervening NOPs and section changes cannot create false passes.
The full **native** alignment-definition regression passes locally, including
the patchable-entry and malformed-option cases. This is a focused regression,
not a local full-CI run. The hosted failure is not described as green; the next
push must validate the correction on GitHub.
