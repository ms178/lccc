## 1. Per-finding verdicts

### AUD-1 (HIGH, "blocker") — LICM hoists volatile loads. **CONFIRMED. FIXED.**

- Pre-fix state: the hoist decision in `src/passes/licm.rs` bound `volatile`
  from the load match, never read it; `is_load_hoistable` had no volatile
  parameter; the comment above the code still claimed "volatile loads must
  execute exactly as written". The `unused_variables` lint was masked
  tree-wide. The audit is exactly right, including the compound factor
  (LOOP-PREHEADER-1's profitability filter does not exclude volatile, so the
  new preheader machinery *creates* the single-block shape the
  derived-pointer hoist path requires).
- Proof of consequence (not just structure): a mutant program with a
  volatile global load inside a loop hoisted the load out of the loop —
  one access instead of N. That is an MMIO/polling miscompile; this project
  boot-tests Linux, so "unreachable" was not an acceptable disposition.
- Fix: the volatile conjunct is restored *before* the dominance check, with
  a debug trace. A new corpus gate `tests/regression/check_volatile_licm.sh`
  (kernel + structural assertion scoped to the loop body at
  `-O2 -march=x86-64-v3`, differential run with LICM on/off, and a negative
  control requiring the plain-load twin to still hoist) is wired into
  **both** `ci.yml` and `scripts/ci_local.sh` (command-parity gate now 97).
  The gate is red on the pre-fix code and green with the fix — verified in
  both directions.
- Agree with the reviewer's P0 exactly as specified. No disagreement.

### AUD-2 (MED) — "late rerun was AArch64-only / VecMaxI32x8 dead on x86". **CONFIRMED FALSE NARRATIVE. DOCS CORRECTED.**

### AUD-3 (MED) — div/LShr preheader hoist lacks dominance. **CONFIRMED. FIXED.**

## 3. Where this review disagrees with the audit

1. **Severity of AUD-2.** The code was correct; only the *story* was wrong.
   MED is defensible for a merged PR (reviewers rely on the narrative), but
   the actionable content of the finding is a documentation bug. Treating it
   as a code defect risks over-correction (e.g. "simplify" the mode
   wrapper). We corrected the docs and left the wrapper alone.
2. **P1(5) as specified.** Re-pointing block A at
   `vectorize_function_late` and re-measuring is a one-off experiment whose
   answer decays the next time the wrapper changes. The 14-shape density
   gate (`scripts/check_minmax_shapes.py`, 14/14 at exact pre-change
   densities) is the standing version of the same measurement; it fails if
   the density drifts *or* if the "dead code on x86" story becomes true
   again. Standing gate > one-off measurement.
3. **Scope of P2.** "No other refactors" is correct *for the fix PR*. The
   integration directive for this session explicitly asked for further
   performance work, which is why this commit also carries the CMP-REPLAY
   peephole (§4) and the RED-UNROLL kill switch. That is a disclosure, not a
   violation: both are standalone, kill-switched, and individually gated.
4. **AUD-5 as MED.** An unmeasured arm swap that cannot be measured in this
   environment is a *disclosure* item, not a merge blocker; MED implies
   action before merge. We kept it with the measurement debt recorded.
5. **The audit's own blind spot (not scored).** It could not see that the
   tree it reviewed was one of *two* concurrent integration lineages
   (this session's #678-fix line and the #681/#682 union). Several of its
   "pre-patch" line references were stale against the union by the time
   either fix landed. Adjudicating against the union and re-verifying every
   reference was necessary precisely because the audit had no toolchain.

## 4. Performance work added in this commit (beyond the audit)

### CMP-REPLAY removal (`peephole/passes/redundant_cmp.rs`)

The audit session's own hard data showed the per-select compare replay:
varint kernel LCCC 50 insns / 6 cmp / 2 cmov vs GCC 42/3/0, Clang 34/1/1.
The pass removes a `cmp`/`test` whose two operand registers are
live-identical across the interval to a later identical `cmp`/`test`, when
the interval contains only (a) flag-neutral instructions, (b) pure flag
readers (cmov/setcc/cmovcc class), or (c) register-pure instructions that
write no operand register family. Soundness rests on the family model:
"operand not rewritten" is checked per GP register *family* (so `sete %al`
correctly blocks a second `cmpl %rax, …` — the byte write aliases the
compared register), with the family order matching `REG_NAMES` exactly.
Memory operands, labels, jumps, and any other flag writer block. At most one
duplicate is removed per scan per site; the pipeline fixed-point loop
re-runs to stability.

- Kill switch: `CCC_PEEPHOLE_SKIP=redundant_cmp` (same mechanism as the
  other peephole passes).
- 12 unit tests, incl. the varint shape, the operand-family alias case,
  the flag-writer-between case, and the re-anchoring case.
- Corpus A/B, 51 programs, `-O2 -march=x86-64-v3`, static insn count:
  7645 → 7637 (−8); changed: aarch64_select_patterns −3, linux_find_bit −2,
  binary_search −1, moving_stats −1, strlen_bench −1; **zero programs grew**.
  (binary_search is the audit session's "shared bounds comparison" shape —
  the reduction is visible end-to-end, which is what the static rank data
  predicted.)

### RED-UNROLL kill switch (from the pre-integration session)

`LCCC_NO_REDUCTION_UNROLL` gates the min/max constant-trip reduction unroll
