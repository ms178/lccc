# `__builtin_cpu_supports`: the runtime CPU model (AUD-CPU-1, final revision)

Status: implemented, rebased onto upstream `main` + `6495e6eb`, verified by
`tests/regression/check_cpu_supports_runtime.sh` (13 gate rows + differential
execution), 9 unit tests in `src/common/cpu_probe.rs`, and the recorded name
census in `tests/data/cpu_supports_name_census.json`.

This document supersedes the fold-based note in
`FOLLOWUP-2026-10-13-audit-fix-session.md` (row AUD-CPU-1) and the earlier
`artifacts/` notes: the fold is gone.

## 1. Why the fold was wrong (measured, not argued)

`scripts/godbolt.py` drives GCC 16.2, Clang 23.1 and the latest ICX. For
`int f(void) { return !!__builtin_cpu_supports("avx2"); }`:

| compiler | `-O2 -march=x86-64` | `-O2 -march=x86-64-v3` | `-O2 -march=raptorlake` | `-O2 -march=x86-64-v3 -mno-avx2` |
|---|---|---|---|---|
| GCC 16.2 | runtime (`__cpu_model`) | runtime | runtime | runtime |
| Clang 23.1 | runtime (`__cpu_model`) | runtime | runtime | runtime |
| ICX latest | runtime (`__cpu_features2`) | runtime | runtime | runtime |

No combination folds, not even the one in which the target *guarantees* the
feature and not even under an explicit `-mno-avx2` denial. The builtin answers
one question — "does the CPU *executing* this program have the feature?" —
and `-march=`/`-m*` describe what the compiler may emit, not what the CPU has.

The same three compilers reject all four constant contexts in which the old
fold silently accepted the builtin:

| context | diagnostic (GCC/Clang/ICX wording) |
|---|---|
| `int a[__builtin_cpu_supports("avx2") ? 2 : 1];` | `variably modified 'a' at file scope` |
| `case __builtin_cpu_supports("avx2"):` | `case label does not reduce to an integer constant` |
| `static int v = __builtin_cpu_supports("avx2");` | `initializer element is not constant` |
| `enum { E = __builtin_cpu_supports("avx2") };` | `enumerator value for 'E' is not an integer constant` |

LCCC now emits exactly these four diagnostics (same wording, correct spans) and
rejects an unknown feature name with GCC's wording
(`parameter to builtin not valid: <name>`) instead of the previous silent `0`.
Enumerators and file-scope array bounds are diagnosed in
`src/frontend/sema/analysis.rs`; case labels in
`src/ir/lowering/stmt_switch.rs`; static initialisers in
`src/ir/lowering/global_init.rs`; the builtin itself in
`src/ir/lowering/expr_builtins.rs` (`CpuSupport::Runtime` is the only
non-error outcome, and it always requires a function to emit the probe into).

## 2. What LCCC emits now

`__builtin_cpu_supports("f")` lowers to a load + AND + compare against a cached
probe word (`src/ir/lowering/expr_builtins.rs::emit_cpu_probe_read`), and the
driver appends `src/common/cpu_probe.rs::runtime_asm` to the translation unit
once, before the first function that needs it. The helper

* reads CPUID leaves 1, 7 (subleaves 0/1), 0xD (subleaf 1), 0x14 (subleaf 0),
  0x24 (subleaf 0), 0x80000001 and 0x80000008, each guarded by the maximum
  leaf the CPU advertises (basic and extended), so no undefined CPUID input is
  ever issued;
* applies the OS xstate gates exactly where libgcc/compiler-rt do (`XGETBV(0)`
  bit 1|2 for VEX, 1|2|5|6|7 for AVX-512, 17|18 for AMX) and clears the
  affected feature bits when the OS does not save that state;
* caches the AVX10 *levels* as bits (`CPUID.(0x24,0):EBX[7:0] >= N`, gated by
  the AVX10 advertisement bit `CPUID.(7,1):EDX[19]`), so `avx10.N` stays an
  ordinary bit test;
* is position independent in all three flavours (x86-64 RIP-relative; i686
  absolute; i686 PIC through a local `R_386_GOTPC` thunk with the base in
  `%esi` because CPUID clobbers `%ebx`), saves every callee-saved register it
  touches, and emits CFI only when the driver enables unwind tables;
* is fail-closed: the words are zero-initialised and only written after a
  successful CPUID, so a probe that somehow ran before initialisation answers
  `0`, never a false `1`.

The `GOT32`/`GOT32X` defect this work exposed (a local GOT-slot symbol folded
to its `.bss`/`.data` section, so the linker added the symbol offset a second
time — 145 instead of 25 in the asserting probes) is fixed in
`src/backend/{elf_writer_common.rs,generation.rs,x86/assembler/elf_writer.rs,
i686/assembler/elf_writer.rs}`; six link pipelines, both architectures, PIE and
non-PIE, are all correct.

## 3. Name space

`tests/data/cpu_supports_name_census.json` is generated by
`scripts/cpu_supports_name_census.py` (batched remote compiles, bisection,
`--diagnostics`), and checked offline in CI
(`--verify-json`, which also fails on source/table drift).

* GCC 16.2 accepts 93 of the 145 candidates; LCCC accepts 114 (a strict
  superset — 21 names are LCCC-only: Clang/Intel spellings such as `pclmulqdq`
  and `rdrand`, `-m`-flag spellings, `avx512er`/`avx512pf`, `bmi`/`bmi2`).
* The six names GCC accepts that LCCC previously rejected are now probed:
  `avx10.1`, `avx10.2`, `clzero`, `movrs`, `ptwrite`, `wbnoinvd` (leaf 0x24,
  0x80000008 and 0x14 additions above). Rejecting them would have broken
  dispatch code that builds with GCC.
* Clang accepts *every* candidate string (unmodelled names fold to 0) — which
  is why the gate treats Clang's set as informational and enforces GCC's.

## 4. Cost

Measured with `tests/workloads/dispatch/run.sh` (callgrind instruction counts —
this VM has no PMU, and shared-host wall time is not evidence).  `probe` and
`control` are the *same* loop, built from one source file, with a probe and
with a plain `volatile` flag read; the difference is the probe, isolated from
the loop's own codegen.  50 M calls, `-O2`, x86-64.

| binary | probe | control | delta / call | one-time init | CRC-32 dispatch |
|---|---|---|---|---|---|
| LCCC (this tree) | 1 200 117 866 | 700 117 783 | **10** | 117 867 | 2 294 484 073 |
| GCC 14.2 (Debian) | 600 121 043 | 600 120 652 | 0 | 121 045 | 1 704 301 657 |
| Clang 19.1.7 (Debian) | 550 121 058 | 550 120 667 | 0 | 121 029 | 1 704 147 000 |

Reading the table:

* **The one-time cost is paid lazily and is smaller than libgcc's**: 117 867
  instructions for the first probe of a program, against 121 045 for GCC's
  `__cpu_indicator_init` constructor — the same CPUID sweep, run before `main`.
  Counted with `-DINIT_ONLY`, which calls the builtin exactly once.  LCCC's
  sweep is smaller because it re-reads the maximum leaf instead of caching it,
  caches AVX10 *levels* rather than the raw version, and stops at the leaves it
  models.
* **The per-call residual is 10 instructions**: 4 are the prologue/epilogue the
  (reachable, once-per-program) initialiser call forces on the function, 3 are
  the guard itself (`load ready`, `test`, `je`), and 3 are register shuffling
  for the extra live range.  GCC and Clang pay 0 because a constructor means the
  probe is a plain, guard-free load of `__cpu_model` — the same shape whether
  the compiler is 14.2, 16.2 or 23.1 (the oracle matrix in §1 shows GCC 16.2 and
  Clang 23.1 emitting exactly that, for every flag set).
* **Before this change the same measurement was 27 instructions per call** (an
  unconditional `call __lccc_cpu_init` at every probe).  `splice_cpu_probe_init`
  now splits the entry block at the first probe-word read into
  `entry → (ready ? hot : cold)`, `cold: call __lccc_cpu_init; goto hot`,
  `hot: <first read and everything after>`: the guard dominates every read, the
  call runs at most once per program, and the hot path is a compare plus a
  not-taken branch.  `check_cpu_supports_runtime.sh` §6 pins the shape.
* **The CRC-32 workload gap is not the probe.**  That program probes once or
  twice in total (its dispatch site is outside every loop); the 590 M
  instruction difference is the table-driven CRC loop itself (~9 instructions
  per four-byte word).  That is loop codegen quality, tracked separately
  (`engineering/FOLLOWUP-2026-10-13-audit-fix-session.md`, performance item),
  not an AUD-CPU-1 cost.

Why the residual is not zero, and why that trade is deliberate: GCC, Clang and
ICX initialise the model in an ELF constructor and accept that a build which
does not run constructors — `-nostartfiles`, freestanding code, a kernel, a
JIT-emitted object, a static binary linked without a startup hook — silently
answers "no features".  That is AUD-SILENT-ZERO-1 in its most dangerous form: a
dispatcher takes the wrong path, and if the guard polarity is ever inverted
upstream, an illegal instruction.  LCCC's probe stays correct in all of those
environments, and the price is one branch per probe plus a frame in the
functions that probe.

## 6. Deliberate deviations (documented, not accidental)

* **Value, not mask.** GCC returns libgcc's raw feature bit mask (`1024` for
  `avx2`), LCCC returns `0`/`1` (Clang's behaviour). C truthiness is identical
  and the builtin's documented contract is "non-zero if supported"; `x == 1`
  tests keep working.
* **XOP/FMA4/TBM/GFNI are VEX-gated** here, ungated in compiler-rt: all four
  are VEX-encoded, so an OS without YMM state cannot execute them either; the
  gated answer is the conservative one.
* **Superset of GCC's names** (see §3), never a subset.
* Naming: GCC spells `rdrnd`/`sha`, not `rdrand`/`sha_ni`; both spellings are
  accepted here, the GCC one is canonical.

## 7. Open items found while doing this (tracked, with reproducers)

* **x86-64 GOTPCREL spelling — FIXED this session.**  The assembler chose the
  relaxable `R_X86_64_{REX_,}GOTPCRELX` from the REX prefix alone, so stores,
  `lea` and immediate compares got a spelling GAS never emits for them.  GAS
  2.47 decides on the *instruction form* (`gas/config/tc-i386.c`,
  `output_disp`): `mov r,m` 0x8b, `test` 0x85, the eight binops both ways
  (0x03/0x0b/0x13/0x1b/0x23/0x2b/0x33/0x3b and 0x01..0x39) and indirect
  `call/jmp/push` (0xFF /2,/4,/6) relax; stores, `lea`, immediate forms and
  the `0F` map do not.  `gotpcrel_form_relaxable` implements the predicate;
  the seven-form battery now matches the pinned GAS 2.47 pair
  (`R_X86_64_REX_GOTPCRELX q1`, `R_X86_64_GOTPCRELX q2`,
  `R_X86_64_REX_GOTPCRELX q3`, `R_X86_64_GOTPCREL q4`,
  `R_X86_64_GOTPCRELX q5`, `R_X86_64_GOTPCREL q6`, `R_X86_64_GOTPCREL q7`),
  enforced by `tests/regression/check_got_slot_local_addend.sh`.
* **i686 keeps `R_386_GOT32` where GAS emits the relaxable `R_386_GOT32X`**
  (the `mov`-load, binop, `test` and indirect `call/jmp/push` forms).  Values
  are correct in every pipeline (the gate asserts exit status 25); this is a
  relaxation/size opportunity that needs the assembler and `lccc-ld`'s
  relaxation to move together — see the follow-up ledger §6.4.

* **AUD-CPU-3 — intrinsics are not ISA-gated** (the hole is in the *permission*,
  not in the builtin). Measured on this tree:

  ```
  $ cat t.c
  #include <immintrin.h>
  __m256i f(__m256i a) { return _mm256_add_epi8(a, a); }
  $ lccc -O2 -march=x86-64 -S t.c -o - | grep -c vpaddb     # 1  <- AVX2 code in a v1 object
  $ gcc  -O2 -march=x86-64 -c t.c                            # error: inlining failed in call to
                                                             # 'always_inline' '_mm256_add_epi8':
                                                             # target specific option mismatch
  ```

  Same for `_mm_crc32_u8` (SSE4.2) under `-march=x86-64`. 268 `BuiltinIntrinsic::X86*`
  variants need a per-intrinsic required-feature set; the honest fix is an
  oracle-derived table (generate it by asking GCC which flag makes each
  intrinsic compile) plus a lowering-time check with GCC's wording, gated by a
  new regression gate. Deliberately not attempted as a partial fix: a gate that
  covers some intrinsics and not others is worse than the documented hole.
* **`__builtin_cpu_is` is not implemented** (GCC has it: `"intel"`, `"amd"`,
  `"znver1"`, ...). Nothing in the corpus uses it; recorded so the name space
  can be closed deliberately rather than by accident.
