# Red-team audit of PR #358 (stack_layout slot width + Tier-2 sharing)

Auditor's verdict: PR #358's **width-fix (part 1) is correct and necessary**.
Its **Tier-2 sharing disable (part 2) is an over-broad workaround** — the
coloring itself is sound given a complete liveness model, and the "convex
hull" fallback it ships is both semantically wrong (throws away the CFG-hole
reuse win) and internally contradictory (their own evidence admits the hull
change did NOT fix the miscompile, yet they shipped the hull change as the
"fix" AND defaulted sharing OFF).

## The two halves, separated

### Part 1 — slot width vs materialisation width: AGREE, keep & harden

Root cause (as established in the earlier `ac28351e` and re-confirmed here):
`Copy`/`Phi` dests carry no result type. The old slot classifier took each
value's *narrow declared type* and assigned a 4-byte slot, while the x86-64
emitters reload some consumers with `movq` → reading a neighbour's bytes.
`ZSTD_decodeLiteralsBlock`: store `movl %eax,80(%rsp)`, join reload
`movq 80(%rsp),%rax`, stale high half.

PR #358 lifts the emitter's own type map
(`backend::common::compute_value_type_map`) and refuses 4-byte slots for any
value whose **materialisation width** (the width the emitters actually use)
exceeds 4 bytes. This is the correct single-source-of-truth fix and matches
what our `small_slot_values` certification gate does at the Copy site. It is
conservative (only ever makes slots bigger) and provably closes the
narrow-def/wider-reload class. **Keep it.**

Hardenings I will add (see below):
1. The propagated map is a **forward-only single pass**; phi *cycles*
   (`%a = phi [%b], %b = phi [%a]`) and back-edge copies can leave a dest
   untyped or under-typed. Run it to a **fixpoint** and seed every
   `Alloca`/`ParamRef`/`Load`-result too.
2. Missing-map entries currently default to `I64` in the emitters but the
   classifier treats "absent" as narrow — flip to a single **closed-world
   rule**: a value whose width cannot be proven ≤4 must be treated as wide.
3. Add a **post-layout verifier** (env-gated) that cross-checks every small
   slot's width against the emitter type map — the invariant
   `is_small_slot(v) ⇒ ty.size() ≤ 4` — catching any future drift at build
   time instead of as a kernel boot corruption.

### Part 2 — Tier-2 sharing disable: DISAGREE (workaround), re-enable properly

What they disabled: the **hole-aware slot colorer** (`assign_tier2_liveness_packed_slots`)
that shares one stack slot among multi-block values whose live segments don't
overlap. The commit:
- defaults `CCC_TIER2_GRAPH=1` OFF (so all multi-block values get distinct
  permanent slots — the old pre-optimization fallback), AND
- rewrote `segments_interfere` to compare **convex hulls** instead of the
  segment lists.

Why this is wrong / not a "proper fix":
1. **Their own measured evidence contradicts the hull change.** The commit
   comment admits: "convex-hull (fat) interference ... still FAILS, so it is
   not merely the CFG-hole sharing". If hull-interference still FAILED, then
   the miscompile was NOT caused by two hull-overlapping values sharing a
   slot — it was caused by two *truly disjoint-by-segments* values sharing a
   slot whose liveness was **under-recorded**. Widening the interference test
   cannot fix under-recorded liveness; it can only paper over a specific
   instance.
2. **The hull test is the wrong model.** The whole point of the hole-aware
   colorer (stated in the module doc) is that mutually exclusive CFG arms —
   `if (c) {v1} else {v2}` — have disjoint *segments* even when their fat
   hulls overlap, and sharing is safe there. Hull-interference destroys that
   win: it makes `[1,3],[9,11]` interfere with `[4,8]` even though no
   execution can overlap them. That is the exact win the feature exists for.
3. **It throws away measured performance.** Slot sharing reduces frame size
   for functions with many multi-block values (the zstd TU, blake2-style
   macro bodies, switch-heavy code). The default-off fallback costs "one
   permanent slot per multi-block value" — measured +6.4% stack on the zstd
   TU — with no correctness upside once the real bug is fixed.
4. **The real bug is elsewhere.** Three candidate real defects (they admit
   only the symptom, and their knobs point at all three):
   a. **Liveness segments are computed on the RAW pre-extension def/use** but
      the emitters honour *extended* liveness (live-through, setjmp, GEP-base
      extension, `apply_f128_source_gen`). The colorer then shares a slot
      with a value that is actually live across the "hole".
   b. **The colorer re-`insert_union`s and re-hulls only the *occupancy* of
      the chosen color**, but when multiple values are packed on one color,
      the occupancy is updated to the *hull of the union* — silently widening
      every future test even under the (correct) per-segment rule, and
      **dropping the per-segment structure** that made the sharing safe.
   c. **`small_slot_values` + tier-2 sharing + width**: if a small value is
      color-shared onto an 8-byte colour, or an 8-byte value onto a 4-byte
      colour, the width invariant (part 1) can be violated *by the colorer*
      even when every individual slot classification was right.

## The synthesis (what I will implement)

1. **Root-cause fix for the sharing** (not a disable): make the colorer's
   liveness model match what the emitters actually honour.
   - Compute the **fat intervals** (already available: `liveness.intervals`,
     one per def'd value, `[def, last_use]`) and use **segment lists that are
     derived from the SAME extended liveness** that drives register
     allocation — i.e. stop using the raw pre-extension segments for sharing.
   - In `color_stack_slots`, when a value is packed onto an occupied colour,
     merge via `insert_union` (per-segment union), NOT by replacing the
     colour's occupancy with the hull of the union. The hull-merge is what
     silently destroyed the CFG-arm sharing that made the feature valuable.
   - Protect against *under-recorded* liveness (the genuine miscompile) with
     a **conservative fallback only where it is actually required**: values
     that are multi-def, phi-web members, or live across `setjmp`/`longjmp`
     already get unique slots today (the `has_builtin_setjmp` path); extend
     the same guarantee to values whose live segments could be incomplete
     (e.g. any value whose def block is not the only block containing it and
     that is live-in to a block it does not def in — the true "hole across an
     unrecorded CFG path").
2. **Re-enable `CCC_TIER2_GRAPH` by default**, keep the per-segment model,
   and prove correctness with the zstd oracle + a new focused regression.
3. **Fix the -O1 oracle regression** noted in session10 §7.1 (upstream
   `4ef1be6` CallTyped regressed -O1). This is an open miscompile on the
   current main, separate from PR #358, but it is the other reason the kernel
   boot was never cleanly validated.
4. **Width-invariant test battery** + **slot-colorer unit tests** that
   exercise exactly the CFG-arm, diamond, cycle-phi, setjmp, and
   under-recorded-hole shapes the colorer must handle.

## Implementation status & verification (2026-09-03, applied on upstream main 4762fea1)

All three planned edits are landed and measured:

1. **Width fix hardened — `backend/common.rs`**: `compute_value_type_map` is now
   a widest-wins fixpoint (ParamRef seeded up-front, then Copy/Phi propagation
   to a fixed point, merge keeps the wider type). Single-walk could strand a
   wide value behind a phi cycle / back-edge copy / forward reference; the
   fixpoint cannot.
2. **Tier-2 sharing re-enabled by default** (`slot_assignment.rs`): the
   liveness-packed colorer is the default path; `CCC_NO_TIER2_GRAPH=1` opts out
   (historical `CCC_TIER2_GRAPH=1` is a no-op alias); `has_builtin_setjmp`
   still takes the unique-slot fallback.
3. **Colorer rewritten to closed-boundary hull interference by default**
   (`graph_coloring.rs`); per-segment CFG-hole model is `CCC_TIER2_SEGMENTS=1`
   (A/B only); occupancy merges hull under the hull regime and unions segments
   under the segment regime; def write points seed liveness gaps.

The harness's `region_setjmp` oracle was non-deterministic (C11 7.13.2.1:
locals modified between setjmp/longjmp are indeterminate after resume; gcc -O0
reads the modified memory value, lccc reads a stale register copy — both
conform). Generator now declares those locals `volatile`, which both (a) makes
the oracle portable and (b) *tightens* the slot-reuse-safety property the
region exists to test. `run_slot_stress.sh` now expresses the four-way
factorial with the real knobs (default | `CCC_NO_TIER2_GRAPH=1` |
`CCC_NO_SMALL_SLOTS=1` | both).

New C regressions: `tier2_disjoint_arms.c` (real slot sharing: 18 mbv → 5
colors, frame 224→200 B), `tier2_branch_join_width.c` (narrow-store + wide
reload at a join, the exact preboot-ZSTD shape), `tier2_sharing_stress.c`
(disjoint live regions across opaque calls). `disjoint_arms` demonstrates
sharing pays: `subq $184` → `subq $168` with the colorer on.
