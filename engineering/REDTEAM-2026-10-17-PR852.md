## Empirical CI finding: sysroot resolver test is host-dependent

GitHub run `39046286866` (CI for `ae5b6a6a…`) records failures in both `Build once and unit tests` and `Assertion-enabled units and corpus`; Clippy and the declared-MSRV job passed. The assertion-enabled annotation identifies:

```text
backend::linker_common::resolve_lib::tests::script_path_with_baked_sysroot_prefix_is_stripped
assertion `left == right` failed ... [src/backend/linker_common/resolve_lib.rs:295:9]
```

The test creates `$SYSROOT/lib32/libc.so.6`, passes the baked path, and expects that same path. The new resolver tries, in order: the doubled sysroot-prefixed candidate, the stripped path in the host namespace, then the as-written path. If `/lib32/libc.so.6` exists, the second candidate wins and the assertion fails. The test therefore encodes a host-filesystem assumption. This sandbox's Debian 12 root does **not** have `/lib32/libc.so.6`, so the hosted failure cannot be reproduced simply by rerunning that assertion here; the source and GitHub annotation establish the mismatch.

The branch fix uses a temporary stripped target and a separate temporary baked target, so it tests the intended priority without relying on `/lib32`. It also centralizes prefix stripping and requires a path-component boundary; otherwise a configured root `/opt/root` could incorrectly match `/opt/root-old/file` and probe `-old/file` relative to the current working directory.

## Vector-varargs ABI: useful direction, incomplete edge coverage

The `VaArgVector` design distinguishes GP-carried vectors from pure-SSE vectors and advances the SysV `fp_offset` by 16 bytes for an SSE vector. The implementation has explicit code for GP/overflow paths and byte-width-limited copies, which are sensible invariants to test. However, `check_ext_vector_varargs_abi.sh` does not exercise all the cases its comments describe:

- Its GCC-cross `vector_size` consumer reads two vector values and one `double`: **three SSE save slots total**, well below the eight-register limit.
- Its LCCC `ext_vector_type` round trip uses **four SSE-carried values** and GP-carried values, again below the limit.
- No fixture exhausts the eight XMM argument registers and then reads an SSE vector from `overflow_arg_area`.
- No vector larger than 16 bytes reaches the claimed carrier-less/MEMORY fallback, and the `-mno-sse` vector path is not exercised.
- The `gcc_ok=0` branch prints `SKIP`, but the later self-leg optimization loop still invokes `$gcc_bin` to link. Thus the advertised optional-GCC skip is not a true skip when GCC is absent or cannot compile the fixture.

These are coverage and harness-contract gaps, not proof that the implementation is wrong. The ABI feature was not imported wholesale here because the current main source lacks it and this environment cannot build or run the compiler; the report does not claim a full cross-compiler validation.

## Additional red-team observations

1. **Kernel source fallback trust boundary:** #852's `prepare_kernel_tree.sh` says the GitHub stable-tree fallback uses signed `v$KVER` tags, but the code checks only `git describe --exact-match --tags HEAD == v$KVER`; it does not run `git verify-tag` or pin/compare a commit digest. In `auto` mode the fallback is used when the tarball download *or checksum check* fails. That weakens the integrity guarantee from the PKGBUILD tarball SHA-256. This should be made fail-closed on checksum mismatch or verify the signed tag against an explicit trusted key before treating the Git fallback as equivalent.
2. **Removed regression gate:** #852 removes the dedicated enum-scope compatibility gate/fixture. The new `md_submodule_enum_compat.c` exercises body-less enum compatible-type behavior, but does not reproduce the old fixture's nested tag shadowing followed by outer-tag restoration or its incompatible-pointer negative control. The new fixture is valuable but does not obviously subsume those assertions.
3. **Unvalidated code after the failing run:** the latest #852 head was pushed after the observed CI failure; there are zero check runs on that exact SHA. The PR's narrative that local FAST passed is not enough to certify this head, and later code changes must not be assumed covered by the older run.
4. **No performance optimization was selected for this patch.** The linker-prefix correction is a correctness fix; no benchmark claim is attached to it.
