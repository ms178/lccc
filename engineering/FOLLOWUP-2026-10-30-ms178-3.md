# ms178-3 follow-up (2026-10-30): RISC-V lccc-ld vs GNU ld 2.47, strided reducer, #1031 follow-ups

Base: `ms178/lccc` main `9bc081312` (#1031 merged; #1028, #1029, #1030 before it). Every number below was
measured on this tree with the pinned oracles (GNU ld 2.47 for RISC-V,
GCC 16.2, Clang 23.1.4, ICX 2026.2) using Callgrind and llvm-mca. The VM has
no PMU, so cycle claims come from llvm-mca `-mcpu=alderlake` (the closest

## RISC-V linker: what changed and why

| Change | Root cause | Evidence |
|---|---|---|
| Allocated `SHF_MERGE` merging (`sections::merge_alloc_sections`) | lccc-ld concatenated `.rodata.str*`, `.rodata.cst*` and `.srodata.cst*` inputs. GNU ld pools them (`bfd/merge.c`) | static glibc link: `.rodata` 113,796 → **110,980 = bfd**; gate `strmerge` 8/8 byte-exact |
| Relaxation resolves merged members through their representative (`LayoutProbe::representative`) | `gp_margin` sized the *member* input, so a pooled constant looked out of section and lost GP relaxation. bfd's `_bfd_merged_section_offset` also makes the representative `sym_sec` | `b_scale`: `lui+fld` pairs → `fld …(gp)`, as bfd does |
| Relaxation trip skips merged members | `inputs_by_merged` placed members after their representative, shifting in-trip addresses | same gate family |
| `.sdata` header flags come from the inputs (`MergedSection::script_write`) | `.sdata` filled only by `.srodata` was written `WAM`, bfd writes `AM`. Layout still places it RW | gate `strmerge` |
| Shared-object PLT kept through relaxation | every import call in an lccc-linked `.so` became `jal 0`; tiny libraries failed with `RvcJump displacement -4262` | gate `shared-import`: library loaded by a bfd-linked program prints GNU ld's line |
| Calls to the library's own default-visibility functions go through the PLT; `-Bsymbolic`/`-Bsymbolic-functions` honoured, `DT_SYMBOLIC` (+`DF_SYMBOLIC` with new dtags) | lccc-ld silently behaved like `-Bsymbolic` and ignored the flags (ELF interposition broken) | `shared-import` default/`-Bsymbolic`/`-Bsymbolic-functions`: the program's `hook` wins exactly when it wins under GNU ld; hosted `.so` `.plt` 0x60 → 0x80 = bfd |
| Imports keep their PLT entry as `.dynsym` `st_value` (`riscv_elf_finish_dynamic_symbol`) | `&strlen` in a `-no-pie` program differed from libc's `strlen` | gate `ptreq-O2`: "DIFFERENT"/rc 1 → "equal"/rc 0; per-symbol dynsym check |
| IPLT slots only for referenced IFUNCs (`_bfd_elf_allocate_ifunc_dyn_relocs`) | static glibc had a second stub + `R_RISCV_IRELATIVE` for `__libc_memcpy` | static `.plt` 32 → 16, `.rela.plt` 48 → 24 = bfd; gate checks both |
| Executable-stack warning + `--[no-]warn-execstack` | bfd 2.47 warns about an executable `.note.GNU-stack` marker by default. lccc-ld was silent | unit test `execstack_warning_matches_gnu_ld`; gate checks the text and the opt-out |
| `PT_GNU_STACK` from markers / `-z [no]execstack` | an always-RW stack made GCC nested-function trampolines fault | new `nested_trampoline.c`: old lccc-ld **SIGSEGV** under qemu (RW), now `RWE` and prints 42, like bfd |
| RW `PT_LOAD` only when the RW segment places bytes; `PT_GNU_RELRO` only when non-empty | lccc emitted an empty RW LOAD (`.tbss`-only TLS) and zero-size RELRO | gate `tls-le` ×4, `bfd_mix` ×16 |
| Shared-object phdr order; merge flags/entsize kept only on full agreement | divergences from bfd's order and from `lang_add_section` | gate shared family |

Design note on the merge. The pre-pass rewrites the input objects once,
before relaxation, as `edit_eh_frame` and `align.rs` already do. The
representative receives the pool; section-symbol addends become `map(addend)`
and symbol values `map(value)`, which is bfd's rule. Members leave the layout
and map, in `sec_mapping`, to their representative's position. The 55
`sec_mapping` consumers therefore need no change, and no synthetic symbol
reaches `.symtab` or `.dynsym`. The rejected alternatives were a synthetic
pool object, which puts the pool at the wrong address and breaks byte
exactness (as x86's `strmerge.rs` does), and threading a map through every
consumer.

Deliberate divergence (unchanged): shared objects keep separate code (R, RX,
R, RW LOADs; no W+X), where bfd maps read-only data executable. The gate
enforces "no W+X, exactly one RX and one RW".

## Strided i32 reducer (x86)

* Displaced streams `(*(u32*)(b+i+4)+k)*3` now vectorize. They used to stay
  scalar, and the stress harness had claimed coverage it did not have; the
  gate now asserts `paddd` in the asm for every family.
* Constant multiplies by `1`, `2^k` and `2^k±1` become shift and add/sub
  (`MulPlan`). The plan is exact modulo 2^32, checked over 0..=65536, the top
  65537 values and every `2^k±1`. `md.c` probe, f() (re-measured on `aeaaea007`: 3,512,000 Ir, output `808b8f4d`):

  | build | Ir |
  |---|---:|
  | lccc before | 7,198,000 (scalar) |
  | displaced streams | 4,922,000 |
  | **+ MulPlan** | **3,512,000** |
  | GCC 16.2 | 7,198,000 |
  | ICX 2026.2 | 4,750,000 |
  | Clang 23.1.4 | 2,464,000 (reads the gaps; the exact-access contract forbids that) |

* `x << 1` stays `pslld`, not `paddd x,x`. Measured: `paddd` was worse,
  3,768,000 Ir and 5015 vs 4681 llvm-mca cycles, because the SSE binary
  emitter routes a same-operand add through `%xmm0` (one extra `movdqa`).
* `byte_load_reassembly` -O2: lccc 19,763,456 Ir, GCC 28,347,541 (−30%),
  Clang 18,064,190. Clang's edge is folding the second compact load into
  `shufps`'s memory operand. llvm-mca: Alder Lake 5343 vs 5345 cycles (no
  gain), Zen 4 5013 vs 4346 (−13%). A legacy-SSE memory operand must be
  16-byte aligned or it faults, so the fold needs an alignment proof from the
  reducer to the emitter. Not done; see below.

## x86 codegen follow-ups

* **`jump_thread` entry-edge guard.** Threading the entry edge into a loop
  body rotated the loop in `count_zero_intermediate_casts.c`
  (portable_bit_counts): repair phis cost +4 Ir per iteration, `main()`
  303,127 → 319,501 Ir, and the codegen gate failed (78 → 82 moves).
  `enters_loop_body` refuses only threads whose target is inside a loop
  the source is not in; bypass threads stay. Now `main()` 303,127 Ir
  (= main) and expat_xml_scan keeps the late pass's gain: 632,276,564 Ir
  vs main 639,471,914 (GCC 16.2 584,810,042).
  Refinement (`iterates_enclosing`): a loop `l` is ignored when the
  thread's path passes the header of an enclosing loop `m` that contains
  the source. Root cause of the two failing merge-loop unit tests: after
  one arm of a merge loop threads (`5→6'→2`), the copy's back edge forms
  an inner loop {2,3,5,6'} inside the header-1 loop, and the other arm's
  latch thread (pred 4, path [6,1,2]) was refused as an "entry". It
  iterates the outer loop; the result is reducible. count_zero's
  preheader thread passes no enclosing header and is still refused.
  Effect: 1/86 benchmark programs change, linux_list_sort 2,300,552,192
  → 2,215,812,439 Ir (main 2,747,282,022; clang-23 2,256,667,537; icx
  2,021,331,753; gcc-16 1,917,501,163); outputs identical to gcc-16.
* **Store-fed indexed folds** (`indexed_store_fold_is_guaranteed`). The
  dead-chain walk kept a store-consumed GEP's offset chain alive because a
  refusing store rematerialises from it. On x86-64 a store through an
  accepted fold cannot refuse (`indexed_fold_ok` documents the proof:
  identical type/shift gate, staging only in %rax/%rcx/xmm0, shared
  operand builders), so default-address-space stores whose base is not a
  register-offset symbol (dynamic freshness refusal) no longer keep it.
  i686/AArch64 keep the conservative rule. 258 program×config asm diffs:
  21 change, none grows, 11 programs lose 1-2 dead instructions
  (base64_enc also a callee-saved push/pop); runtime output = gcc-16 at
  `-O2`, `-O2 -fno-pie`, `-O3 -march=x86-64-v3` (30/30).
* **`check_rmw_sib_folds` causality arm.** Codegen now emits
  `bins(, %idx, 8)` itself (the series' `single_use_load` peel stop), so
  skipping the `shl_sib` peephole no longer brings a `shl` back and the
  old mutation arm failed. The arm is now proven on the input it exists
  for: with the codegen fold disabled (`CCC_NO_FOLDED_INDEX_LIVENESS=1`)
  the peephole alone reaches the scaled form, and skipping it keeps the
  `shl`. Main and this series both pass.
* **RA wave 3** tries the hazard-free pool before the depth-exact pools:
  glibc_memcmp 8 → 6 callee-saved pushes.

## Session 2026-10-31: call-argument homes, scaled-index fold, rebase on #1037

### Outgoing call-argument register preferences (x86-64 SysV)

`collect_outgoing_arg_prefs` (`regalloc_helpers.rs`) prefers, for a value
passed to direct calls in one consistent integer slot, that slot's register,
so it is computed where the call reads it (`fill`: `testq; je; movq
%rsi,%rdx; movl $7,%esi; jmp memset`, GCC's code).

* They are **soft** (`RegAllocConfig::reg_prefs` -> `LiveRange::reg_pref`),
  not `reg_hints`. In this allocator `reg_hint.is_some()` is the ParamRef
  ordered-copy contract: never evicted, never exchanged, excluded from
  hot-web stealing. The first version wrote outgoing slots into `reg_hints`
  and so made every argument value unevictable: lz4's hash-table base took
  `%r15` and the match loop's end pointer went to the stack (25 -> 35 stack
  operands, `cmpq 40(%rsp)` twice per iteration). A preference is honoured
  by `find_free_register` and wave 3a only.
* A value with an incoming-parameter hint gets no preference. The first
  version overrode the incoming hint when its register was a lower argument
  slot; that bought nothing (the staging copy out of the incoming register
  is the same one move) and broke the contract above.
* Measured against the same tree with preferences off (static: 86
  benchmark programs; dynamic: Callgrind Ir of every program whose code
  changed, outputs identical):
  * `-O2`: 15 better / 1 worse, -26 instructions, -3 stack operands.
  * Ir: loop_patterns -6.92 %, sqlite_varint -1.67 % (`-Os`),
    zlib_ng_adler32_combine -1.61 % (`-O2`) / -1.59 % (`-Os`),
    binary_trees -0.45 % (`-Os`); expat_siphash24 +0.081 % (`-O2`, one
    move per call in its 2M-call loop: the preferred cold value no longer
    advances the rotation cursor, so `off` lands in `%rsi`, which `len`
    wants). Everything else within +-0.002 %.
* **Measured and rejected: preference-aware rotation ("claims").** Sparing,
  in the rotation scan, registers that another overlapping unassigned range
  prefers (function-wide claim list, one allocator per wave) fixed
  expat_siphash24 (-0.081 %) and gained aarch64_select_patterns -3.03 %,
  zlib_ng_adler32 -3.40 %, linux_rbtree -0.70 %, but lost loop_patterns'
  -6.92 % and regressed gzip_longest_match +1.64 %, sqlite_varint +1.67 %,
  zstd_double_fast +0.49 %. Rotation picks are order-sensitive; claims move
  unrelated picks. Three regressions of 0.5-1.7 % for one of 0.08 % is not
  acceptable. A future attempt needs a cost model, not a scan filter.
* Also tried: dropping preferences on loop-spanning ranges. No effect on
  the `-Os` cases it targeted and it halved the `-O2` gain; reverted.

### Sign-extending widen into a 32-bit register result (found by `ci_local.sh --fast`)

`check_shift_signext_fold.sh` failed on the tree with the preferences:
`shifted()` became `movl %edi,%r11d; shrl $24,%r11d; movsbq %r11b,%rdi`
instead of main's `movl %edi,%edi; sarl $24,%edi`. The preference homes
the `I8 -> I32` cast result in `%rdi`, and the register-direct widen
(`emit_int_widen_move`) always wrote `movsbq`/`movswq`, which
`fold_copy_logical_shift_signext` (32-bit shapes) does not match. Not a
preference bug: the same cast through the accumulator is `movsbl`.

`sext_widen_writes_32` now emits `movsbl`/`movswl` for a 32-bit result
unless a raw 64-bit reader needs the canonical home, the contract every
32-bit ALU result follows (`needs_sext_values`); U32 results always (their
canonical home is zero-extended). `PendingWiden` records the decision, so
the PF-15 flush still equals the immediate form. Two textual
extending-load lists in `compare_branch.rs` lacked `movswl`/`movzwl`;
an unlisted line was only conservatively refused (post-scan carrier check),
but the boolean-reload arm accepted `movswq` and must accept the 32-bit
form too.

Measured against the same tree without it (86 programs x
`-O2`/`-Os`/`-O3`): 2 programs change, 0 instructions difference, every
change a 1:1 `movs?q` -> `movs?l` replacement; Callgrind Ir csv_field_sum
-14, moving_stats equal, outputs identical. Also tried and rejected: the
same rule for accumulator-staged sources (`emit_cast_from_accumulator`).
There the source is usually a just-loaded `movsbq` value, the second
extension becomes a 64-bit copy, and copy propagation collapses 64-bit
chains but not the 32-bit `movl` pair (popcount_loop_density: +2
instructions in its argv parse).

### Peephole: bare shift as a scaled index (`relay_and_lea.rs`)

`shlq $s,%T` (s = 1..3) feeding `leaq (%B,%T),%D` becomes
`leaq (%B,%T,2^s),%D` when `%T` dies there and the shift's flags are dead
(the loop_memset start address `d + 4*i`). Restricted to `leaq` consumers:
memory consumers of a shifted temporary are `fold_shift_into_sib`'s
(its memory-operand arm), and `check_rmw_sib_folds.sh` contract 2c proves
that ownership (skipping `shl_sib` must keep the `shl`). The 3-component
LEA (`addq $c; leaq (b,i)` -> `leaq c(b,i)`) stays refused: slow LEA on
Skylake-class cores.

## Open, measured, not fixed in this series

1. **`-pedantic` / `-pedantic-errors` (GP-10).** Chosen as a separate
   patch; not in this series. Main only reserves the warning slot
   (`error.rs`: "no pedantic diagnostics are implemented"). It needs a
   GCC-16 gated pedwarn corpus.
2. Same-operand SSE binary ops copy through `%xmm0`
   (`emit_sse_binary_128`). One extra `movdqa` per op. Nothing in this series
   emits that shape any more.
3. SSE2 `VecMulI32x4` recomputes `pshufd $0xf5` of a loop-invariant splat
   every iteration. It only affects multipliers without a shift-add form
   (gate family `h`). For a splat the shuffle is the identity; fixing it
   needs splat tracking in the x86 emitter.
4. Aligned `shufps m128` fold for compact strided loads: Zen 4 −13%, Alder
   Lake 0%. Needs an alignment proof.
5. Hosted RISC-V images: `.plt`, `.rela.plt` and import values now match
   bfd. What remains has no runtime effect: GNU ld reserves the 16-byte
   `.got.plt` header and an 8-byte `.got` header in static links (lccc-ld
   24 bytes smaller), and exports crtbegin's weak undefined
   `_ITM_(de)registerTMCloneTable` (value 0, referenced by no dynamic
   relocation, so never bound) - `.dynsym` 9 vs 7 entries.
6. Scalar `leaq g(%rip)` rematerialized inside loops (x86 regalloc), seen in
   the `md.c` scalar tail.
7. `fill_off` (`memset(d + off, 2, n - off)`): 9 instructions vs GCC's 7.
   `n` dies at the `sub` that defines the length, but the allocator treats a
   last use and a def at the same instruction as overlapping, so the length
   (preferring `%rdx`) cannot share `n`'s `%rdx`. Sharing a dying operand's
   register with the result is sound only where codegen reads every
   operand before writing the destination; it needs that proof per
   lowering, not a scan change.
8. i686: a `do ... while (++i < n)` latch emits `cmpl; setl %al; movzbl
   %al,%eax; jl` (two dead instructions per iteration, plus `xorl
   %eax,%eax` before the loop) although the final IR is `Cmp` -> its only
   use, the `CondBranch`. `emit_int_cmp_impl` materializes, so
   `detect_cmp_branch_fusion` returned `None` on i686 for this block;
   x86-64 fuses. Pre-existing (main-era build identical). Next step: log
   `value_use_counts[cmp]` at the detection site for `-m32`.
9. loop_memset has no guardless do-while form (`do d[i] = 0; while (++i !=
   n);` with the entry jumping straight into the loop). Exact at pointer
   width or for a pointer IV (a 2^W-trip run or a counter wrap would
   touch more bytes than any object holds), not for a narrower counter
   (x86-64 `unsigned i`: a 4 GiB object is legal). GCC transforms it at
   `-m32`.
