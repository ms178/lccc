Ground truth from the godbolt oracle (GCC 16.2, `-Os -m16 -mregparm=3`):

`addl $48,%esp` cleanup); a 40-byte `.bss` array gets **no `.align` at all**
under `-Os`. All three lccc behaviors diverged from that oracle; all three are
now GCC-parity or better.

## 3. Fix A — stack-parameter direct homing (i686)

`ParamClass::StackScalar` parameters no longer get a homing copy
(`movl 220(%esp),%eax; movl %eax,188(%esp)`). The ParamRef dest's frame slot
is **redirected onto the caller's argument slot** via
`param_direct_homes: FxHashMap<i64, i64>` consulted by `slot_ref`/
`slot_ref_offset`, so every load, store, spill and coalesced alias resolves to
the single authoritative location. Rationale: the i386 psABI gives the callee
ownership of its incoming argument slots — the same model GCC codegen uses.

Soundness is guarded by `stack_param_direct_home_eligible`, which rejects the
redirect when any value sharing the slot could store beyond 4 bytes:

* typed instruction dests sharing the slot wider than 4 bytes (a wide spill
  would clobber the *adjacent argument's* home in the caller frame);
* `Alloca` dests by data size (`result_type()` is `Ptr`, so the scan checks
  the Alloca's `size` field);
* the backend's pre-scanned width sets (`wide_values`, `i128_values`,
  `vector_values`, `vector128_values`) for Copy-only webs;
* over-aligned allocas (effective address ≠ raw slot base).

Kill switch: `CCC_NO_PARAM_DIRECT_HOME=1`.

**Measurement (boot corpus, identical flags):** all 49 homing pairs
eliminated; `.text` 22598 → 22509. Net per-parameter saving is the 11-byte
pair minus the +3-byte disp32 penalty on each subsequent access — the honest
reason this is not 49×11: most boot parameters are read 2–4 times.

## 4. Fix B — push-based outgoing-argument staging (i686)

`emit_call_stack_args_impl` now marshals scalar stack arguments with
**right-to-left pushes** (`pushl $imm` for constants — GAS picks the imm8
`6a` form; `operand_to_eax` + `pushl %eax` otherwise) when every stack
argument is a 4-byte scalar and the outgoing area is exactly the pushed bytes
(`stack_boundary <= 4`). `esp_adjust` tracks each push, so subsequent operand
loads see the shifted frame exactly as the `subl` model would; the
caller-side `addl $N,%esp` cleanup is byte-identical because the pushed total
equals the old area size. `const_stack_arg_imm` — the shared single source of
truth for a constant argument's 32-bit image — guarantees the pushed four
bytes equal the bytes the store path produced.

Eligibility mirror-checks the space computation class-by-class; wide
(F64/I64/U64/D64), struct, F128, I128, register-class and zero-size
arguments keep the `subl` model. Kill switch:
`CCC_NO_PUSH_ARG_STAGING=1`.

**Measurement:** boot `.text` 22509 → **22212** (−297 B, −1.3 % of the whole
corpus from call sites alone).

## 5. Fix C — `-Os` data alignment is now GCC-parity (all targets)

`effective_align` promoted every global ≥ 16 bytes to 16-byte alignment
unconditionally. GCC's DATA_ALIGNMENT only promotes when `!optimize_size`;
under `-Os` a 40-byte `.bss` array gets no `.align` directive at all
(godbolt-verified). The promotion is now skipped when the invocation is
`-Os`/`-Oz` (`optimize_for_size` threaded from `CodegenOptions` through the
new `ArchCodegen::optimize_for_size` trait method into `emit_data_sections`).
Natural ABI alignment (`g.align`) is always kept; explicit
`aligned(N)`/custom sections are still honored verbatim.

**Measurement:** `.rodata` 1387 → 1364, `.data` 140 → 124, `.bss` 4960 →
4924 in the boot corpus. Note `boot_params` (4096 B) keeps its explicit
`aligned(PAGE_SIZE)` and is immovable — it is the floor of the gate metric.

## 6. The gate, honestly

The 32 KiB setup gate is a *gate*, and the flat-image geometry matters more
than raw `.text` here: `.pecompat` carries `sh_addralign = 4096`, pinning
everything after it to offset 0x6000. `.text` (ending at 0x5b4c) sits in the
hole below that pin, so `.text` cuts beyond the pin do **not** move `_end`;
the movable `_end` mass is `.rodata` + `.data` + `.bss`, which Fix C shrank.

| metric | session-58 | this session | Δ |
|---|---|---|---|
| gate `_end` | 31168 | **31104** | −64 B |
| headroom | 1600 | **1664** | +64 |
| flat setup.bin | 30372 | **29911** | −461 B (−1.5 %) |
| boot `.text` | 22598 | **22212** | −386 B (−1.7 %) |

The remaining `_end` mass is 4096 (`boot_params`, explicit page alignment) +
~780 B of protocol-mandated VESA/E820 buffers + ~1580 B of pinned-section
content — the gate metric is now within ~1 KB of its structural floor while
`.text` retains 1268 B of banked free space below the 0x6000 pin. **The
metric to optimize further is the flat image and compressed payload, not
`_end`.**

## 12. This session's feature: x86-64 direct push forms for MEMORY-class stack arguments

The x86-64 staging loop already pushed (post-`subq`), but every push went
through the accumulator: `operand_to_rax` + `pushq %rax` = 6-9 B per
argument and a serialised %rax chain across the whole marshalling window.
Ground truth: GCC 16.2 emits `pushq $imm`; Clang 23.1 emits
`pushq mem(%rsp)` (both confirmed via the godbolt oracle on a
restacking wrapper); ICX matches Clang.  lccc now selects, per argument:

| source               | form                 | bytes (was) |
|----------------------|----------------------|-------------|
| imm in [-128,127]    | `pushq $imm8`        | 2 (6)       |
| imm in imm32         | `pushq $imm32`       | 5 (6)       |
| zero (any width)     | `pushq $0`           | 2 (3/6)     |
| fresh GP home        | `pushq %reg`         | 1-2 (5-6)   |
| plain scalar slot    | `pushq off(%rsp|%rbp)` | 5-8 (6-9) |
| parity pad           | `pushq $0` (was `subq $8,%rsp`) | 2 (4) |

Soundness law (documented at `x64_stack_arg_push_imm`): `pushq $imm32`
writes all eight slot bytes as `sign_extend(imm)`; for eight-byte
containers the value must fit imm32 exactly (the `0x80000000` unsigned
test in the guard), for sub-eightbyte scalars the upper lane is
ABI-unspecified and every reader takes the low lane.  Register pushes are
freshness-gated (`fresh_home_of`; stale homes fall back), %rbp only in FPO
mode, XMM homes fall back.  Slot pushes require a plain scalar slot (not
alloca, not i128/F128/vector payload, not a small slot — the fallback's
load re-establishes the type invariant a blind push would not).  The
accumulator cache is deliberately NOT invalidated: no form writes %rax.

ABI conformance note, closed with three oracles: lccc's eightbyte stride
for sub-eightbyte stack scalars matches GCC 16.2, Clang 23.1 and ICX
(psABI rounds MEMORY-class scalars to eightbytes); the "pack at 4 bytes"
hypothesis was tested and **rejected by data before any code moved**.

### The direct-home guard defect — found, root-caused, fixed (test-side)

The suite's one red row exposed a defect in THIS document's own session-59
guard test, not the compiler: `i686_stack_param_direct_home.c` called
libc `printf`/`puts` while compiled with `-mregparm=3` — which passes
arguments in registers, so every libc call read garbage (glibc is cdecl;
GCC 16.2 emits the identical register-argument call, so both arms were
"broken" identically and the ABI violation was invisible in a
printf-comparison methodology that could not link its GCC arm).  The
session-59 suite "passed" because the GCC arm could not link in that
sandbox and the row was skipped — the test never actually ran to a
verdict.  Fixed by making the test freestanding (checksums observed
through the exit status + a volatile sink; regparm-free `-DPRINT_REF`
derivation build; every EXPECT_* row emitted by one reference run so no
constant can drift from one arm's semantics — two of the session-59
constants HAD drifted: EXPECT_B/C were hand-baked and only EXPECT_A was
oracle-derived).  All four rows verified against gcc -m32 -O0/-O1/-O2/-Os
and both lccc trees.

Also fixed in their tooling: `boot_ab_size.py` ran the compiler with
kernel-relative source paths from its own work directory — it now resolves
against `--kernel` (the harness' `cwd=kernel` compile calls already did;
the fix makes the whole tool cwd-robust).
