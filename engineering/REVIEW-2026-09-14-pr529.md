## Agree (each independently re-verified, not taken on trust)

1. **C7 `/0` fix (`0xC0 | reg`).** Correct x86 encoding; the audit's survey
   of the other C7 writers checks out. The regression gate is well built:
   the deterministic per-register probe (hand assembly, no allocator luck)
   plus the static C7/0 scan; the SKIP-on-shape-change in the compiler-driven
   half is acceptable precisely because the deterministic probe does not
   depend on compiler output shape.
2. **i686 `is_tls_reloc` table** (`14..=19 | 24..=37 | 39..=41`). Verified
   entry-by-entry against 2.47 `elf/i386.h`, including the 38-is-SIZE32
   exclusion. Kept as-is.
3. **defsym hardening design** (deferred evaluation, 1-based counter,
   linker-defined-name classification, dynamic-alias rejection). All three
   GNU message shapes re-measured byte-for-byte (counter-0 syntax rule,
   colon-less `/ by zero`, UND-alias error); the "visible only through a
   shared library is not defined" rule confirmed against real `ld`.
4. **LAM-U48 grouping** (`FEATURE_1_LAM_U48 = 0x4 | 0x8`). Skeptical at
   first ("LZCNT_LAM grouping" is an odd comment), but measured GNU `ld
   -z lam-u48` emits LAM_U48 **and** LAM_U57 while `-z lam-u57` emits U57
   alone — the constant is right and is now pinned by a differential
   harness case (`prop_note_z_lam_u48_sets_both_bits`, S05).
5. **PT_NOTE/PT_GNU_PROPERTY plumbing, sectionless-`.so` dynsym recovery,
   standard-symbol seeding.** Sound; the `or_insert` seeding order was
   verified empirically (`int end = 42;` links and runs rc=0 under both
   linkers — user definitions win, matching GNU PROVIDE). The `PT_GNU_
   PROPERTY_` local const duplicates the new shared constant, but that
   file is consistently hermetic (`SHF_ALLOC_` etc.) — style, not a defect.
6. **Loud refusals for unsupported dynamic TLS** instead of silent
   mislinks. Correct philosophy for this project; the error texts name the
   missing capability precisely.
7. **`setup_oracles.sh` lld monorepo fix.** The distro-LLVM version-mismatch
   diagnosis is careful measured work; monorepo-root configure is the only
   self-consistent setup.

## Disagree (each with measurement and fix)

1. **x86-64 `is_tls_reloc` narrowing (44–51 removed) — wrong.** The audit
   claims "the lccc assembler never emits the binutils 2.41+ relaxable
   extensions". It does: `encoder/core.rs` `gottpoff_type`/`tlsdesc_type`
   select `CODE_4/CODE_6` TLS types for REX2/EVEX, and `emit_rex_or_rex2`
   emits REX2 whenever EGPRs are involved. The linker's own
   target-aware classifier (`elf/symbol_table.rs`, untouched by this PR)
   already lists 44/45/47/48/50/51 as TLS — the narrowing made the two
   classifiers disagree, against the folding-corruption rationale the PR's
   own trait doc states. (The comment also cites a phantom `CODE_1` that
   does not exist in `x86-64.h` — the header was not checked.) Fixed in
   S03 (widen to the exact TLS subset; 43/46/49 stay foldable), covered by
   unit tests on both sides of the boundary.
2. **i686 ABS-GOT slot-vaddr + RELATIVE — wrong, and a silent mislink.**
   The added comment asserts "GNU ld gives every ABS GOT entry an
   R_386_RELATIVE, so the slot ends up holding its own vaddr". Measured
   twice (S03 and S05): GNU `ld -m elf_i386 --defsym k=100` on a plain
   `R_386_GOT32` emits **zero dynamic relocs** and slot = `0x64` (the
   value). The PR's behavior would make `k@GOT` reads return the slot's
   own address instead of 100. Fixed in S03 (revert + root-cause fix at
   resolve time); verified end-to-end on the current tree (slot bytes
   `64 00 00 00`, only the JUMP_SLOT reloc remains).
3. **`--isa-level=` / `-march=` linker options — non-GNU invention.**
   GNU ld has no such options (only `-z isa-level-report=`, which is
   different). The fields were write-only, the three files contradicted
   each other (cet.rs docs: "the ISA level is *not* a linker option";
   args.rs: "not injected into the property note"; lccc_ld.rs comment:
   "OR the ISA level into the property note"), and the `-march=` parse
   used substring matching (`.contains("v2")`). Removed in S03; the real
   interface (`-z x86-64-{baseline,v2,v3,v4}`) was implemented instead,
   with GNU's exact accept/fatal/warn rules measured and pinned.
4. **`__bss_end__` symbol — fabricated.** Added as "defined by GNU ld,
   referenced by glibc/musl". Measured: `extern char __bss_end__` fails a
   gcc link with `undefined reference`, while `end`/`edata` PROVIDE-
   resolve fine. Defining it makes lccc accept links GNU ld rejects.
   Removed in S05 (both the seeder and the defsym allowlist), with a
   comment citing the measurement so it is not re-added. (`end`/`edata`
   kept: GNU PROVIDEs them.)
5. **defsym straight quotes — nearly-verbatim.** GNU uses backtick-open
   (`` undefined symbol `b' ``); the PR emits `'b'`. Fixed in S03; the
   body is now byte-identical to GNU (verified with `od`).
6. **(Above) CI red misattributed to clippy** — it is 16 rustfmt diffs.
   Fixed; clippy on the head is clean.

## Partial: `--no-undefined-version` (B right, then I over-corrected)

The flag is real GNU interface ("Disallow undefined version"); the PR
stored it write-only. S03 then wrongly DELETED it, demoting a real flag
to the unknown-option warning. S05 restores it properly per each path's
own idiom: the builtin parser accepts and records it (same status as
`--threads`, with an honest not-enforced doc comment), while `lccc-ld`
routes it to the existing accepted-but-not-implemented warning — the
tier that file reserves for "a diagnostic the user asked for", which is
exactly what an unenforced strictness flag is. Enforcement (version-
reference checking) remains a TODO, now stated in the code.

## Gate assessment

`i686-tls-ie-relax` as extended here is a good gate: structure checks
(STT_TLS preserved through folding), the deterministic six-register
runtime probe, and the static scan form three independent tripwires, and
the audit documents the kill-proof (revert → SIGILL exit 132). (An
earlier draft of this review claimed the `ccc=${LCCC_BIN:-
target/fastbuild/lccc}` default points at a binary the fastbuild does
not produce — that was wrong: `target/fastbuild/lccc` IS built, the
default works, and the gate runs bare. Corrected before snapshot.)
