No claim of universal optimality, exhaustive bug absence or approval from

## R1 — GP register renaming ignored fixed ISA operands (confirmed, repaired)

`rename_family` changed text, not architectural operands. Three newly added
optimizer regressions failed against the imported tree:

* Copy/commutative folding removed the definition of RAX feeding `mulq`. The
  following use of the high result made RAX dead **after** MUL, but the old
  RAX value was still an implicit **input**. A MAY-write mask is not proof
  that a reader's operands can be renamed.
* Copy folding renamed a shift's explicit `%cl` count to `%sil`, which has no
  encoding. The newly added adjacent-load/product-range path did the same.

The first two paths predate PR824; its new adjacent path expands the same
unsafe helper's reach. All three defects belong to the cumulative audit.

Alternatives: disabling the passes loses their measured profitable fusions;
forbidding RCX globally also rejects legal addressing, byte moves and BMI2
variable shifts. Instead the shared renamer rejects overlapping architectural
implicit operands, stack-pointer substitution, and only the fixed CL count of
legacy shift/rotate families. Product-range walks also stop on opaque MAY-write
instructions. Existing high-byte restrictions remain. Positive controls retain
ordinary CL reads, RCX addressing, BMI2 shifts and renaming a shift destination.

The original three tests failed; repaired focused load-op-fuse tests pass.
The shift suffix matrix additionally covers ten opcode families and five
spellings. Native control: original high product **2**, illegal rewrite **0**.
GNU assembler accepts the original CL shift and rejects the actual `%sil`
rewrite. The architectural controls extend the existing FAST/hosted witness
gate, rather than creating an uninvoked test. Logs are in
`evidence/pr824-redteam/gp-*`.

## R2 — masked vector moves created false copy facts (confirmed, repaired)

`vector_copy::vec_operand` deliberately strips EVEX decorations to identify a
register. `parse_vec_copy` incorrectly reused that identity as a value equality.
For `vmovdqa64 %xmm1,%xmm2{%k1}`, inactive lanes retain XMM2, not XMM1; with
`{z}` they become zero, still not XMM1. The copy propagator consequently changed
`vmovq %xmm2,%rax` to read XMM1. Both negative Rust tests failed before repair.
Native AVX-512F/VL controls produce merge original=UINT64_MAX/illegal=0 and
zero original=0/illegal=UINT64_MAX. These are architecture witnesses, not a
claim that the C frontend emits every masked register-copy form.

Reject decorated operands at copy-fact admission, shared by propagation,
bracket coalescing and private-copy widening. Keep decoration-aware register
identity for interference scans: rejecting identities there would hide reads
and writes. No mask-constant analysis exists here, so assuming an all-ones mask
would be unjustified. The regression matrix covers XMM/YMM/ZMM, both masking
modes, masked bracket entry/exit and duplicated-source scalar merge forms.
The complete focused vector-copy selection passes **58 tests**. The native
controls are wired into the existing FAST/hosted gate and explicitly skip only
the native AVX-512 witnesses on older CPUs; Rust legality checks are mandatory.

## Validated bounded-unsigned follow-up (S22; FAST acceptance still separate)

The byte hot loop exposed a missed **controlling header** guard:
`U64 phi(0, iv+8); (iv+8) <= 4096`. The whole-loop affine proof now admits
unsigned widths only when the constant-seeded induction phi and its controlling
exit comparison are both in the header, the positive step and predicate match
the type, and every value through the **first failing comparison** is in range.
For the normalized increasing guard, compute the first failing induction value
by ceiling division from the seed; check both that value and its sum with the
nonnegative addend against the type's bounds. This proves ordinary ordered
arithmetic throughout the executed sequence, rather than incorrectly applying
ring algebra to unsigned comparisons. The seed itself is checked, not just
seed+C. Runtime seeds, wrapped entries, unsupported high-bit constant spellings,
mixed signed predicates, noncontrolling comparisons and nonheader guards are
refused. The context-free rotation-clone fold stays signed-only. The broader
pre-existing signed proof is not certified by this narrower extension.

The isolated fastbuild candidate passed 24 focused loop-rotation/verification
Rust tests; the old affine regression gate also passes. The new gate checks
m64/m32 × O0/O1/O2/O3/Os against GCC 16.2, with IR/SSA verification and four
O2/O3 runtime disable controls. Positive debug counters and wrapped-entry
refusals are pinned independently. Against S21's pre-optimization behavior,
the runtime/model tests pass but the positive fold assertion fails as intended;
against the candidate the entire gate passes. Exhaustive four-bit enumeration
covers 131,072 cases (9,366 admitted); the seeded eight-bit sample covers
300,000 (20,828 admitted). This is a model check, **not exhaustive verification
of the compiler or its 32/64-bit input space**.

All **45 Callgrind pairs** complete with matching outputs and no failures.
Compared with frozen S21, byte reassembly changes **82,351,772 → 72,111,772**
(simulated Ir ratio **0.875655378**, 12.4345% fewer instructions) and XML scan
**1,667,885 → 1,651,229** (ratio **0.990013700**, 0.9986% fewer). The other 43
have identical Ir. The byte assembly removes the offset LEA from the controlling
header and backedge compare, using `cmp $4088, iv`. Across the retained byte
changes relative to S17, the reduction is approximately 12.50%, not a hardware

**23 Memcheck executions pass**: all fifteen measured/hash-checked candidate
