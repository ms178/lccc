# Red-team audit: PR #1178 (`arena/460be56e-lccc`)

Branch head `9e2f978`, base `fc8350a` (`main`). Toolchain: pinned `harness-cache-8`
(Rust 1.99.1, GCC 16.2.0, Clang 23.1.5, GDB 18.1, binutils 2.47), fastbuild
preset, 4 GiB swap active.

## 1. CI state: red, two independent defects

| Job | Outcome | Cause |
|---|---|---|
| Clippy (`--all-targets`, `-D warnings`) | **fail** | `clippy::items_after_test_module` in `src/frontend/sema/type_checker.rs` |
| Frontend and ABI contracts (shard c of 3) | **fail** | `check_ms_abi_varargs.sh` dies with SIGSEGV at `-O2`/`-O3`/`-Os` |

Both reproduce locally and both are introduced by the patch.

### 1.1 The clippy failure is a shipped debug probe

`src/frontend/sema/type_checker.rs` carries, verbatim from the patch:

```rust
// TMP-PROBE-BEGIN
fn tmp_typeof_probe(site: &str, expr: &Expr) {
    if let Some(path) = std::env::var_os("LCCC_TMP_TYPEOF_PROBE") {
        ... OpenOptions::new().create(true).append(true).open(path) ...
    }
}
// TMP-PROBE-END
```

called from two sites (`"plain"`, `"scoped"`). This is investigation scaffolding:
it formats every `typeof` operand (`{expr:?}`) and appends it to a file named by
an environment variable, inside the *semantic analyser*, for every translation
unit. `fc8350a` has none of it. Beyond the lint it is an unbounded diagnostic
side channel in a released compiler and a silent I/O dependency on user input.

### 1.2 The segfault: a pre-existing entry-alloca invariant, newly reachable

Reproduction (extracted verbatim from `check_ms_abi_varargs.sh`):

```
lccc -O0  -> PASS        lccc -O1 -> PASS
lccc -O2  -> SIGSEGV     lccc -O3 -> SIGSEGV     lccc -Os -> SIGSEGV
CCC_DISABLE_PASSES=i128_split -> PASS
```

GDB at the fault (`wide+295`, `movzbl (%rbx),%r8d`): `%rbx` holds
`0xdc00000000000000`, which GDB shows is **the 8-byte payload of the
`struct small` argument itself**, not the address of it. The emitted sequence
that produces it:

```
movq (%rsi),%rbx        # F128 copy inlined as a 16-byte SSE load (src width)
movq (%rsi),%rbx        # later 8-byte load of the *cursor* value, emitted at a
                        # point where %rsi no longer held the cursor slot
movzbl (%rbx),%r8d      # SIGSEGV
```

Root cause, in three steps:

1. `src/ir/lowering/func_lowering.rs` merges the deferred `entry_allocas` *after*
   the "initial contiguous run of `Alloca`s" in block 0. Every consumer of that
   block assumes the run is the *complete* alloca set: `mem2reg`
   (`find_promotable_allocas`) promotes only the leading run, `split_ranges`
   (`stack_map`) places only those entries, `isl::lower_instruction_typed`
   decides "16-byte slot <-> `%rax`/`%rdx` pair relay" from it.
2. In `wide()`, an intra-block `Alloca` (`__builtin_convertvector` scratch,
   emitted by `self.emit` mid-body) precedes `Value(13)`, `Value(17)` and the
   wide `Value(3)`. So `Value(3)` — the `u128` home — is **not** in the leading
   run, and its home is instead reached through `GetElementPtr { base: Value(6),
   offset: 8 }` (`Value(57)`).
3. `isl` therefore models `Load ptr=Value(57) ty=U64` as a *general* 8-byte load
   and lets it take the pair-relay path, which reads `(%rsi)` assuming the slot
   is the `%rax`/`%rdx` pair home. `%rsi` there is the F128 copy source.
   `i128_split` is what removes the 16-byte `U128` load that would otherwise
   force the correct relay for the whole function, so the broken 8-byte path
   becomes reachable.

`i128_split` does not rewrite `GetElementPtr` — its `splittable_homes` accepts a
wide alloca whose address is taken through a GEP, and it splits a load through
that GEP as if it were a field access on the home. **That is the patch defect:**
a wide local split as a "home" must be reached *only* by loads/stores of the
alloca value itself.

Both defects are the same class: a conservative consumer (mem2reg, split_ranges,
isl) is handed an IR shape it never modelled, because a producer took a shortcut
(merge after the run; GEP-addressed wide home).

## 2. Measured verdicts

* `i128_split` is the only pass whose removal changes the outcome, and it is
  correct on every shape where the wide home is directly addressed
  (`tests/bench/k_bn_mul128.c` stays green, `-O1` unaffected).
* Clippy: exactly one error, `items_after_test_module`; `-D warnings` therefore
  fails the whole gate before any other lint is reported.
* No other job failure is attributable to the patch: `Build and package
  compiler`, `Differential correctness and measured IPA/LRS witnesses`,
  `Rust 1.99 relocation value contracts` and the AVX-512VL oracle all pass.

## 3. Fix plan (ordered, each independently verifiable)

1. Delete the `tmp_typeof_probe` scaffolding (the probe fulfilled its purpose:
   the red-team matrix in `engineering/REDTEAM-2026-11-11-I128-TYPEOF.md` §4
   records the result).
2. Gate `i128_split` homes on **direct addressing**: a split home's uses must be
   loads/stores whose `ptr` is the alloca value; any `GetElementPtr`, `Copy`,
   call, or other use disqualifies that home (matching mem2reg's own rule).
3. Make the entry-alloca merge preserve the contiguous-run invariant: merge
   deferred allocas into the leading run, and let the mid-body allocas follow
   the run rather than splitting it.
4. Regression gates: an alloca-not-in-leading-run fixture driven through the
   Microsoft variadic shape, plus a source-level pin that `i128_split` never
   accepts a GEP-addressed home.
