Base: `ms178/lccc` main `dc878b3c8`. Every entry was reproduced before
the fix and re-measured after it. Unless stated otherwise, the reference
oracles are GCC 16.2, Clang 23.1.4 and ld.bfd/GAS 2.47.

## Red-team verdicts on upstream work

**#985.** Agree with: `is_opaque_control_transfer`, `lea_add_fuse`, the C23
defaults, `return_home`, and the `identical_blocks` logic. Disagree with:
- the `pow2_cmov` liveness (over-conservative; fixed);
- the `.loc` unit test, which encoded a `-g` artifact (rewritten);
- the i686 `parse.rs` leniency, a misdiagnosis of compressed input (now
  strict, with decompression).

**#988.** Agree with:
- the content-addressed agent cache and the offline freshness gate (its own
  self-tests and `test_agent_toolchain_cache.py`/`test_toolchain_cache.py`
  pass, 19/19);
- verifying mold 3.0.0 by SHA-256 and a real link probe;
- the `kver`+pins build stamp for kernel `relocs`;
- splitting the trapv matrix into one script per ABI. The coverage is
  unchanged: all 6,776 cases per ABI, and the 910-trap total still pinned.

Disagree with the cost model behind the three-shard frontend split. The
1,130 s was the core-dump handler, not the matrix, and the measured shards
ran 2,177/2,137/619 s against the 623 s each that the commit message
claimed. The 2.47.50 snapshot string in the restore self-test fixture is
cosmetic. The real lock pins the 2.47 release tarball (`154ab23b…`, the
same bytes as `ensure_gas_247.sh`).

**#989/#990.** Agree with:
- `PR_SET_DUMPABLE` in the parent (better than this series' per-child call,
  which was dropped);
- store-to-load forwarding for aggregates;
- the common-page-size validation.

Disagree with:
- the trapv lane plan (left at 535 s per leg; re-split above);
- "`--warn-common` is ignored" (bfd implements it; now forwarded and
  implemented);
- withholding i686 `__BMI__` (GCC 16.2 defines it for `-m32 -mbmi`);
- the stale `Got32x` guard.

**#992.** Agree with dialect- and kind-aware severity (`default_errors`,
`effective_warning_config`): 21/21 exit codes on the probe set match gcc-16.
Disagree with the CI step being appended by hand rather than placed by
`scripts/ci_lane_split.py`. The type model cannot reach GCC's qualifier
diagnostics. `CType` carries no qualifiers (`analysis.rs`,
`transparent_member_accepts`), so:
- `char *q = (const char *)p` gets no `-Wdiscarded-qualifiers` warning;
- `const char **c = (char **)pp` and `char *const *w = (const char **)z`
  compile (rc 0), where gcc-16 rejects both with
  `-Wincompatible-pointer-types` (rc 1).

Closing that gap means carrying qualifiers in `CType`, a change to the core
frontend type.

**#993.** Agree with the operand-constraint work: 24 edge probes
(incomplete records under `*`, `->`, `[]`, `sizeof`, `_Alignof`,
`offsetof`, `typeof` and `_Generic`; `&*p` and `&s` on incomplete types;
`void *` indirection in value, discarded, `typeof` and `sizeof(&*v)`
contexts; `.`/`->` on the wrong operand) match gcc-16 in exit code and
warning count under both the default options and `-Wall` (48/48). Agree
with the hand-removal from `verify_ir_gate_files.txt`: the cause is
recorded, and a regeneration would shift every other entry. Disagree with
appending `check_operand_diagnostics.sh` to the existing severity step by
hand: the lane plan kept that step at 1.67 s. Here it is 2.45 s (+0.78 s
measured) and the frontend lane is re-split by `scripts/ci_lane_split.py`
(270.0/270.0/269.9 s, membership unchanged). Separately, the driver
tolerates `-pedantic`/`-pedantic-errors` without implementing them, and
says so in a warning: `void *v; ... v[0];` is rc 1 under gcc-16
`-pedantic-errors` (`-Wpointer-arith` as an error) and rc 0 under lccc.

## Scheduled next (ms178-2.patch, decided 2026-10-27)

- lccc's AArch64 and RISC-V linkers copy no `.debug_*` section into
  executables or shared objects (gdb has no file:line on lccc-linked cross
  binaries), and AArch64 static and dynamic executables have no
  section-header table. Measured with `dbg2.c`/`far.c`: AArch64 0/0/8
  section headers (static/dynamic/shared), RISC-V 19/25/20, `.debug_*` 0
  everywhere.
- `__builtin_cpu_is`/`__builtin_cpu_supports` at -O2: the init guard's cold
  call keeps a frame in a leaf (`subq $8, %rsp`), and the feature-word load
  stays inside loops that GCC 16.2 hoists it out of.
- Qualifiers in `CType` (decided 2026-10-27: in ms178-2): the nested
  pointer conversions that gcc-16 rejects must error, and dropping a
  qualifier on conversion must warn (`-Wdiscarded-qualifiers`), with a
  gcc-16 differential gate.
