## Backlog audit for §5.2

The x86 section was re-read before editing. The most relevant structural debts were:

- small integer/classifier returns were still lowered through the generic 64-bit return path after register allocation, leaving artificial `movq %rN, %rax` copies;
- several peepholes had to reason around 64-bit copies generated by type-erased codegen rather than canonical 32-bit zero extension;
- the bitmap classifier shape (`btq %rcx, %mask`) used by GCC for Expat-like name scanning was not recognized.

Items already considered complete were not reopened: IS-01 (safe masked SIB/indexed GlobalAddrs), IS-03 (64-byte AVX copies), IS-12 (gated BMI ANDN), IS-28 (SWAR popcount), and the dead MachInst allocator removal.

## Implemented changes

### 1. Canonical 32-bit integer return loading

`src/backend/x86/codegen/returns.rs` now intercepts integer returns whose type is at most 32 bits and loads the operand through a new `X86Codegen::operand_to_rax_i32`.

`src/backend/x86/codegen/emit.rs` implements that helper:

- constants use `xorl %eax,%eax` for zero and `movl $imm,%eax` otherwise;
- a value already in `%rcx` uses `movl %ecx,%eax`;
- allocated GPR homes use `movl %eReg,%eax` when the producer type is 32 bits or smaller;
- stack homes use width-consistent `movzbl`, `movzwl`, `movl` or `movslq` instead of calling the 64-bit-only `value_to_reg("eax")`, which previously could emit invalid `movq slot, %eax`;
- XMM, untyped or 64-bit values fall back to the existing generic path.

This directly addresses a structural ISel/peephole issue: ABI zero-extension is now represented at return lowering instead of being repaired later by text peepholes.

Examples:

```asm
# before
f:
    cmpl $65, %edi
    setge %sil
    movzbl %sil, %esi
    movl %esi, %edx
    movq %rdx, %rax
    ret

# after
f:
    cmpl $65, %edi
    setge %sil
    movzbl %sil, %esi
    movl %esi, %edx
    movl %edx, %eax
    ret
```

For a genuinely 64-bit return the 64-bit move remains correct and intentional.

Regression guard: `tests/regression/check_return_32bit_zeroext.sh`.

### 2. Variable bit-test peephole

`src/backend/x86/codegen/peephole/passes/local_patterns.rs` now recognizes:

```asm
movabsq $MASK, %base
shrq    %cl, %base
andq    $1, %res
cmpq    $0, %res
setne   %cc
```

and rewrites it to:

```asm
movabsq $MASK, %base
btq     %rcx, %base
setc    %cc
```

The pattern is intentionally narrow:

- the shift amount must already be in `%cl`/`%rcx`;
- the base must be a constant bit mask loaded immediately before the pattern;
- the result mask must be exactly bit 0;
- labels, jumps, calls and other barriers stop the pattern;
- `%rcx` cannot be the SETcc destination.

On x86-64, `BT` with a register bit index masks the index modulo 64 and stores the selected bit directly in CF, so the rewrite has the same architecture-level semantics as the variable shift/mask/compare sequence for all values in `%cl`. It removes the integer dependency on the shift result and matches GCC's bitmap-classifier lowering.

Unit guard: `variable_bit_test_replaces_shift_mask_compare` in `src/backend/x86/codegen/peephole/passes/mod.rs`.

## Remaining §5.2 follow-up

1. **Expat name scan / IS-06:** drive if-conversion or MachInst selection so the ASCII/UTF-8 classifier can reach the `btq` form. The current CFG uses many `setae`/`movzbl`/branch blocks; GCC uses a compact compare tree plus one `btq`.
2. **SQLite varint / IS-07 and IS-10:** investigate branch/cmov and flag-fusion policies. Avoid enabling if-conversion broadly without beating SQLite and gzip.
3. **find_bit / IS-11:** GCC uses `andn` plus a cmov/ffs tree rather than `tzcnt`; the existing gated ANDN helps only part of this shape.
4. **MachInst profit model / IS-17:** do not raise the 32-instruction cutoff until gzip/expat are measured. The current model still needs a real profit function rather than an instruction-count heuristic.
5. **Memory operand folding / IS-05 and IS-13:** revisit after RA-23 because several folds are blocked by accumulator/immediately-consumed placement assumptions.
6. **Oracle workflow:** keep using `scripts/codegen_oracle.py` for static instruction/load/spill comparisons. Add function auto-discovery in a later cleanup so static functions inlined away by remote compilers are not silently reported as zero.
