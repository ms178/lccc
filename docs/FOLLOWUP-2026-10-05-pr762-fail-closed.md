## Alignment / fill / OOM hardening (2026-10-06, GAS 2.47 red-team probe law)

Everything below is pinned by the `gas247_*` unit tests (6 test fns,
~60 assertions) against a ~45-probe GAS 2.47 red-team session; the
probes also fixed several pre-existing x86 defects found while using
`elf_writer_common` as the reference implementation:

- **`MAX_DIRECTIVE_FILL = 256 MiB`** (`elf/writer_base.rs`, re-exported
  via `backend::elf`): single-directive ceiling for alignment padding,
  `.zero`, `.space`, `.fill`, `.org`, and *regenerated* (post-relaxation)
  align runs.  Beyond it GAS's own verdict is free-disk state (tmpfs
  993 MiB vs a 14 G runner) and cannot be pinned, so a deterministic
  Err is the only reproducible answer.  Applied at parse time wherever
  a `Vec` is built before the writer can intervene.
- **Signed-shift bucket** (`align >= 1<<63`, what `.p2align 63/64/-1`
  clamp into): no raise ever; pad skipped by a positive cap (tested
  BEFORE the error — `p2align 63,,5 @1` assembles per GAS); @0 no-op;
  @1 uncapped -> Err.  Negative exponents clamp to **63**, not 0.
- **x86 defects fixed**: (X1) absurd-branch errored before the max-skip
  test; (X2) 4 GiB materialization cap lowered to the shared ceiling;
  (X3) `max-skip <= 0` now means unlimited (`,,0`/`,,-1` pad — the old
  code rejected `,,-1` and skipped at `,,0`, both backwards); (X4)
  `AsmItem::Zero(u32)` -> `usize` with negative->0 (`.zero -1` was a
  4 GiB-1 allocation, `.zero 2^32` truncated to 0); (X5) bare
  `.balign`/`.align` are align-1 no-ops (bare `.p2align` still errs).
- **`.fill` law** (all three arches): non-positive repeat/size -> 0
  bytes; overflowing `repeat*size` -> 0 bytes; element clamped to 8;
  literals in 2^63..2^64-1 take their two's-complement (negative)
  pattern, > u64::MAX is an expression error (pinned in
  `asm_expr::gas247_literal_range_edges`).
- **riscv** `.align`/`.balign` no longer fail-open (`unwrap_or(0/1)`);
  `emit_align_with_reloc` propagates the align `Result`; `Directive::Zero`
  goes through `emit_fill`.
- `fixup_alignment_markers` now returns `Result` and refuses to
  regenerate padding above the ceiling (relaxation can grow a run past
  the apply-time check).

## NOBITS / fill-budget / default-section hardening (2026-10-06, S09)

Pinned by 15 new `gas247_*` rows measured against GAS 2.47 on **both**
the x86_64 and aarch64 targets (same `read.c` generic law):

- **NOBITS store law**: in a `SHT_NOBITS` section, a store whose *raw*
  value is non-zero is an error — "attempt to store non-zero value in
  section `X'"` — checked before truncation (`.short 256` and
  `.long 4294967296` store zeros and are still rejected).  String
  directives get GAS's wording ("attempt to store non-empty string"),
  `.fill` its own ("attempt to fill section `X' with non-zero value",
  raw value — `.fill 4,1,256` rejected).  Zero stores, all-zero
  strings, and POSITION directives (`.zero`, `.space` with any fill
  byte, `.org`, `.p2align` with any fill) are legal and only advance
  the location.
- The law is enforced through `nobits_guard` / `nobits_string_guard`
  and by making **every writer store return `Result`** (`emit_bytes`,
  `emit_u16_le`, `emit_u32_le`, `emit_data_integer`,
  `emit_data_symbol_ref`, `emit_placeholder`, arm `record_sym_diff`) —
  the type system forces every call site (~57 across the three
  writers) to propagate instead of silently dropping content into
  `.bss` (the old behavior: serialized file correct, fail-open accept).
- **`MAX_TOTAL_DIRECTIVE_FILL = 512 MiB`**: assembly-wide budget
  (`fill_budget_used` + `charge_fill`, both writer stacks) closing the
  N x 256 MiB `.zero` amplification the per-directive cap cannot.
  Charge happens before allocation everywhere; `fixup_alignment_markers`
  charges only NET growth (sustained-fill semantics — the transient is
  bounded by the per-directive cap); the x86 align apply was
  restructured decision -> charge -> materialize so a refused pad
  leaves no raise, no marker, no bytes.
- **`.fill` with a non-zero value materializes at APPLY** (`Fill
  { total, elem, value }` in all three parsers + shared
  `emit_fill_pattern`): the parse side no longer builds an `Ascii`
  `Vec`, so the writer can see the live section (NOBITS raw-value law)
  and the budget.  `.fill 4,1,256` in `.bss` is now an error where the
  old path accepted it after truncating to zeros.
- **Bare input** behaves like GAS: leading content (`.byte`, `.zero`,
  `.ascii`, `.fill`, `.p2align`, label-only input) lands in the
  default `.text` (x86's Align arm needed an explicit `ensure_section`
  — a bare `.p2align 4` previously created nothing and dropped the
  alignment; GAS gives `.text` sh_addralign 16, size 0).
- **Creation/raise alignment law**: sections are *created* at
  sh_addralign 1 (`.text;.byte 1` -> 1, AX `.section` -> 1); the first
  instruction raises the containing section to the instruction
  alignment via `note_instruction` (aarch64 `.text;nop` -> 4,
  riscv -> 2; x86 does NOT raise — measured `nop` -> 1, and x86's
  `reconcile_section_alignments` stays markers-only to match).
- `fixup_alignment_markers` errors now name the directive kind
  (`.org` vs `.align` vs `.lccc_tight_loop`).
- riscv `.org` remains deliberately `Ignored` (kernel
  alternative-macro size assertions) — no writer apply path; confirmed.
- **Deferred**: length-only/zero-RSS NOBITS representation for
  `.bss > 512 MiB` (triggers documented in `elf_writer_common`);
  riscv64 GAS binary not provisioned this session (law probes ran on
  x86_64 + aarch64 — the same generic `read.c` code path).
- **Environment note**: a harness container restore does not carry
  /usr packages; without `sudo apt-get update && sudo apt-get install
  -y gcc-multilib g++-multilib libc6-dev-i386` (what
  `arena_session_restore.sh` runs), six i386 gates fail with
  `bits/libc-header-start.h` / `cannot find -lgcc` — that is
  environment, not code.

### Deviations register (WP5)

Verdict-level differences that are **documented, deliberate, and
re-verified against both oracles**; message-level differences keep the
verdict identical:

1. **llvm-mc dialect fork on alignment exponents**: llvm-mc 23.1.2
   rejects alignments above `exp 31` (`invalid alignment value`) where
   GAS 2.47 accepts or skips them; the GAS verdict is the pin (matrix
   rows are `re-`derived from GAS every run).
2. **>u64::MAX decimal REPT count**: GAS says `bad or irreducible
   absolute expression`, we say `bad integer: ...` — both rc=1, same
   row verdict; wording not copied (our wording names the token).
3. **Free-state class** (uncapped absurd fills, llvm under memory
   limits): excluded from the table by design; covered by unit tests
   asserting our deterministic Err (`MAX_DIRECTIVE_FILL` et al).
   **Extended 2026-10-07**: the expansion ceilings
   (`MAX_EXPANSION_TEXT` / `MAX_EXPANSION_LINES`) belong to the same
   class, with the oracle side measured rather than assumed — GAS 2.47
   accepts a 41 KiB `.irp` that expands to 30,000,000 lines (rc 0,
   5.4 s, 30 MB object) and would accept a `.rept 5000000` in ~0.5 s,
   while llvm-mc has no `.rept` budget at all and runs until the
   allocator stops it (`rc` 133/134 under `ulimit -v`).  Our verdict at
   those sizes is the deterministic Err on purpose (OOM-prevention law:
   `Vec<String>` line vectors cost several times the raw text), it
   fires *between* blocks rather than after the product exists, and
   `gas247_irp_expansion_ceiling_x86` pins the wiring.
4. **Shift counts outside 0..64**: GAS warns and yields 0 (measured:
   `.rept 1<<64` assembles with zero repetitions); we yield 0 silently
   (`asm_expr::eval_shift`, pinned by
   `gas247_shift_out_of_range_is_zero`) instead of Rust's masked shift
   (`1<<64 == 1`) or a panic (`1<<-1`).
5. **`sh_offset` = cursor aligned to `min(sh_addralign, 8)` (4 on
   ELF32)** — the full GAS law, re-measured 2026-10-07 across nine
   probes (PROGBITS and NOBITS, cursors 0x41/0x43/0x44/0x49, aligns
   1..2^62, both ELF classes).  The first-pass reading ("never
   padded") was wrong in the harmless direction: every probe then had
   an 8-aligned cursor.  Padding to a raised 2^62 (full-align reading)
   aborted the writer in `Vec::with_capacity`; raw cursor (no reading)
   disagreed with GAS at every misaligned boundary.  NOBITS stamps the
   same capped cursor and consumes no bytes (align 16 after cursor
   0x43 -> 0x48; align 1 -> 0x43), replacing the legacy `sh_offset=0`
   no toolchain emits.  Pinned by
   `gas247_sh_offset_never_padded_to_addralign`,
   `gas247_sh_offset_is_capped_cursor_alignment`, and every
   `--check-lccc` row that raises an absurd alignment.
6. **Zero-divisor expressions match GAS, warnings and all**: `x/0`
   yields `x`, `x%0` yields 0, both rc 0 (GAS warns "division by
   zero"; `.rept 7/0` expands 7 times).  The old hard Err rejected
   input GAS accepts -- a fail-closed divergence on legal source.
   `MIN/-1` and `MIN%-1` were Rust panics-in-every-profile; they now
   carry the measured bignum low bits (i64::MIN / 0), and `+ - *`
   evaluate with wrapping ops so debug and release profiles cannot
   disagree.  Pinned by `gas247_divmod_zero_and_wrap_law` and two
   matrix rows per target.
7. **Crash is never a verdict** (matrix runner law): exits outside
   {0,1} -- signals, OOM-kills, Rust panics (101) -- raise a harness
   error instead of `REJECT`, so a resurrected SIGABRT can never
   silently satisfy a REJECT row (same law the operand matrix pinned).
8. **x86-only jump-range class** (`p2align-x64` group): GAS's tc-i386
   refuses to jump over nop padding in executable sections beyond
   reach; aarch64 and data sections do not have this class — the group
   name documents why the rows are x64-only.
9. **Multiply-by-constant step latency is measured, not assumed**
   (2026-10-07, `X86Tune::mul_const_plan`): the plan budget is now in
   **cost units** — LEA steps cost the row's new `lea_scaled_latency`
   (2 ticks for the scaled-index `LEA_B_IS` form on Golden/Raptor Cove
   per `uops.info`/`InstLatX64`, 1 on SNB..ICL and on Gracemont, 2 on
   Zen), ALU/shift/neg steps cost 1 — and a plan is emitted only when
   `cost < imul64_latency`.  The old "1 cycle per step" mispricing let

   3; rdtsc dependent chains 2.53 vs 2.04 cyc/iter, 1-LEA `x9` 1.36)

10. **Macro-nesting depth is a GAS-pin, not an llvm-mc pin** (2026-10-07):
